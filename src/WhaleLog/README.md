## 产出长什么样

每天一份 Markdown，人工可读、可以直接进 Git。归档过的文件按类别分组列在同一个文件里：

```markdown
---
date: 2026-09-11
entries: 3
done: 2
files: 4
---

# 2026-09-11 工作记录

## 今日小结
把归档链路的版本判定调通了，顺手补了自测。

## 事项
- [x] `09:20` 梳理归档流程和版本判定规则  _工作_
- [x] `11:05` 和设计对齐悬浮窗收起交互  _沟通 / 悬浮窗_
- [ ] `14:30` 补大文件采样指纹的边界用例  _工作_

## 归档文件

_共 4 个，按类别分组。原文件都在原位置，没有被移动过。_

### 汇报材料

- **2026-W37 周报.xlsx** · 18 KB · 11:49
  - 位置：`D:\工作\周报\2026-W37 周报.xlsx`
  - 命中规则：汇报与总结
- **报告.docx** `v3` · 1.4 MB · 12:04
  - 位置：`D:\工作\归档测试\报告.docx`
  - 命中规则：汇报与总结

### 代码

- **intake_service.py** · 12 KB · 10:31
  - 位置：`D:\repo\whalelog\intake_service.py`
  - 命中规则：源代码
```

`index.json` 里存的同一份数据（多了指纹、版本链、快照路径），程序读的是它；
Markdown 是给人看的视图，每次改动都会重新生成。

> **老数据修复**：1.3.1 之前的版本有个 bug —— 跨天再归档时新版本会粘在首次归档那天，
> 于是产生它的那天页面反而空着。`python tools\repair_archive_dates.py` 能按版本历史
> 把这类记录拆回各天，默认只预览、加 `--apply` 才写（写前自动备份，程序运行时拒绝写入）。

## 功能

### 1. 当日记录
每天一个 Markdown 文件，写完自动落盘，不需要按保存。每条记录带时间、分类、自由标签、完成状态和耗时。
支持前后翻日期回看，底部有今日小结输入框。

**点日期栏可以展开整月日历**，用来快速跳转和回溯：翻到上周找某天的记录，比连点十几次「‹」快得多。

- 有记录的日子在数字下面点一个小圆点，一眼能看出哪天写过东西；面板底部还会汇总"本月 N 天有记录"
- 今天带一圈强调色描边，当前选中的那天是实心高亮
- 非本月的日子变淡但仍可点，省掉"先翻月再选"这一步
- 未来的日期不可选（和「›」按钮的规则一致），也不会让你翻到未来的月份
- 固定 6 行 × 7 列共 42 格，所以翻月时面板高度不跳
- 鼠标悬停有提示（几月几号、星期几、有没有记录）
- **面板底部有个「跳到」输入框**，知道是哪天就直接敲：
  | 写法 | 解析为 |
  |---|---|
  | `9/23` `9-23` `9.23` | 当年 9 月 23 日；今年还没到就按**去年**同一天 |
  | `0923` | 同上（紧凑 MMdd） |
  | `2026-09-23` `2026/9/23` `20260923` | 明确的那一天 |
  | `9月23日` `9月23号` `2026年9月23日` | 一样认得 |
  | `昨天` `今天` `前天` `大前天` | 相对今天 |
  | `23` | 只填日号 = **当前显示的这个月**的 23 号 |
  - 边打字边给反馈：`→ 2026-09-05 周六`；不合法就直接说原因（`没有 2026-02-30 这一天`、`本月 23 号还没到`）
  - 打开面板时键盘焦点直接在输入框里，敲完 `Enter` 就走
- 再点一次日期栏、点面板外面、或按 `Esc` 都能收起

选日期走的和「‹ › 回到今天」完全同一个 `LoadDay` 路径，行为一致。

**当天归档的文件也列在这一页**，接在事项下面，一天归档几个就顺着往下堆几个：

```
──────────────────────────────
 今日归档的文件  [ 3 个 ]   去归档 ›
──────────────────────────────
 ● 第三季度汇报.pptx  v1
   汇报材料 · 8 MB · 9月11日 16:02
 ● 数据汇总.xlsx  v1
   表格数据 · 420 KB · 9月11日 15:20
```

卡片样式和「文件归档」页**共用同一个 `DataTemplate`**（`FileCardTemplate`）——
两处各写一遍的话，改一处忘了另一处就会长得不一样。顺序也一致：按拖入时刻从新到旧。

几个细节：

- 这一段只跟**当前查看的日期**走，不受「文件归档」页「只看当天 / 全部」筛选的影响
  （两边是两个独立的集合，`_dayFiles` 和 `_files`）
- 当天没有归档文件时整段收起来 —— 外面的空提示已经说了"把文件拖进来"，
  再挂一行"0 个文件"只是噪音
- 在今日记录页拖入文件后会自动滚到这一段，否则清单接在事项后面、很可能落在可视区之外，
  刚拖完什么反应都看不到

### 2. 拖拽归档
把文件（或整个文件夹）拖到主面板任意位置即可归档。会自动：

- 读取文件名、大小、修改时间、完整路径
- **按规则分类**（见下文），并记录命中了哪条规则
- 计算内容指纹，判断这是新文件、新版本，还是内容没变
- 把「文件在哪儿」写进当天记录和索引

**归属日期跟着当前查看的日期走。** 你在看 9 月 7 日的记录时拖入文件，它会记到 9 月 7 日
（这样可以补录过去某天的文件）。这个规则光看界面猜不到，所以拖拽横幅会显式写出目标日期：

```
今天视图：把今天的文件拖到这里
历史视图：把文件拖到这里 → 记入 9月7日
          归入 2026年9月7日 的记录，不是今天。
```

同一个文件**第二天改了内容再拖进来**，会新记一条：前一天那条留在前一天（还是 `v1`），
新版本记在当天（`v2`）。翻哪一天都看得到那天归档过什么 —— 这是归档记录，
不是文件清单。同一天里反复改则只升当天那一条的版本号。

文件列表上方有「只看当天 / 全部」两个筛选：前者只显示当前查看日期的文件，后者显示全部。
胶囊文案是「当天」而不是「今天」，因为它跟着你正在看的那一天走。

**「全部」视图按归档日期分组**，一天一个日期栏，栏间从新到旧；每条记录自己也标着归属日期：

```
┌──────────────────────────────────────────────┐
│ ● 今天 · 9月11日                     2 个文件 │
├──────────────────────────────────────────────┤
│ ● 第三季度汇报.pptx  v1                      │
│   汇报材料 · 8 MB · 9月11日 16:02             │
├──────────────────────────────────────────────┤
│ ● 数据汇总.xlsx  v1                          │
│   表格数据 · 420 KB · 9月11日 15:20           │
└──────────────────────────────────────────────┘
┌──────────────────────────────────────────────┐
│ ● 周三 · 9月9日                      2 个文件 │
├──────────────────────────────────────────────┤
│   …                                          │
```

栏头文案带相对日期（今天 / 昨天）和星期；跨年时会补上年份，否则「9月7日」是哪一年看不出来。
没有归属日期的历史记录单独归到最后一栏「未标注日期」。

> **原文件永远不动。** 不移动、不重命名、不删除，只读取元数据和算指纹。
> 这是硬性设计约束——任何自动搬文件的行为，规则一写错就是数据事故。

### 3. 版本标记

归档记录的粒度是 **一个路径 × 一天 = 一条记录**。
同一个文件 9 月 16 日归档一次、9 月 17 日改了内容再归档一次，那是两个独立动作，
各记一条、各自属于那天 —— 翻 9 月 16 日看到 `v1`，翻 9 月 17 日看到 `v2`。
同一天里反复改则只升当天那一条的版本号，不会刷出一堆重复行。

对每个文件算 SHA-256 指纹，然后：

| 情况 | 判定 |
|---|---|
| 同一路径、**这一天**已归档过、指纹相同 | 重复归档，不产生新版本 |
| 同一路径、**这一天**已归档过、指纹不同 | 同一天里改了再存 → 当天那条的版本号 `+1` |
| 同一路径、**这一天还没**归档过 | 新的一天 = 新的一条记录，版本号接着版本链往下走（前一天那条留在前一天） |
| 不同路径、版本链里已有相同指纹 | 「与 v2 内容一致」，不产生新版本 |
| 不同路径、指纹全新 | 挂到同一条版本链的下一个版本号 |

> 判断「这一天归档过没有」必须连日期一起问。只按路径问的话，升版本会把记录
> 一直挂在首次归档那天，而当天页面、「只看当天」、月历圆点、日报周报看的都是
> 归属日期 —— 结果是「今天明明归档了，今天的页面却是空的」。
> 快照也按这一版归档的那天放：`archive\<日期>\<文件名>\v<N>_<原文件名>`。

版本链的分组键 = 归一化主文件名 + 扩展名。归一化会剥掉 `v2` / `第 3 版` / `(1)` / `_final` / `_副本`
这类版本痕迹，所以 `报告.docx`、`报告_v2.docx`、`报告(3).docx` 会串成同一条链。

一次拖进整个文件夹时，里面的文件会**按修改时间升序**处理，旧文件拿低版本号。
不排序的话枚举顺序取决于文件系统，谁先拿到 v1 是随机的。

大文件（默认超过 200MB）不做全量哈希，改用「文件长度 + 首尾各 4MB + 均匀采样 16 段」的组合指纹。
这种指纹带 `sample:` 前缀，永远不会和全量指纹相等，所以不会出现「采样值碰巧相同就误判内容一致」。

**可选快照模式**：开启后每个版本会额外复制一份到 `archive\<日期>\<文件名>\v<N>_<原文件名>`，
版本才真的"留下来"了、可以回滚。默认关闭，因为它占磁盘。

### 4. 快速记录（全局快捷键）
默认按 `Ctrl+Alt+N`，屏幕光标旁弹出一个小输入框，敲完 `Enter` 就存进当天记录，
不用先找小鲸鱼、再打开主面板。`Shift+Enter` 换行，`Esc` 取消，点别处自动收起。

- 输入框里可以直接点分类胶囊，不用回主面板改
- 以 `#标签` 开头可以顺带打标签：`#周报 整理完第三季度数据`
- 快捷键可以在设置页里「录制快捷键」改成别的组合；被其他程序占用时会明确告诉你
- 注册用的是消息专用窗口（`HWND_MESSAGE`），所以从托盘静默启动（不创建主面板）也能生效

### 6. 桌面小鲸鱼

- 无边框、透明、置顶，直接用 `DSniang1.png` 原图，不做任何裁切
- 拖动移动，松手自动吸附到最近的那条屏幕边缘
- 不操作时收起成贴着边缘的小圆头像（用 `whale-head.png`），鼠标移上去展开
- 常驻显示：今天几条记录、归档几个文件、距下班还有多久
- 单击鲸鱼打开主面板，单击状态条手动收起/展开，右键是托盘菜单
- 位置、大小、透明度全部记忆；右上角角标显示未收尾的条数

「大小」和「透明」两个滑杆**拖动时实时生效**，不用等设置落盘（落盘有 700ms 的节流，
连画面一起等的话拖动全程鲸鱼都不动，看着就像这个设置没用）。

大小范围 0.7×–1.6×，**窗口尺寸和内容缩放出自同一个系数** —— 用 `LayoutTransform`
让鲸鱼、文字、间距整体等比缩放。只改窗口宽高的话，放大时内容不变（窗口里一片空），
缩小时内容撑不下就被裁掉十几个像素。收起态的小胶囊收窄到 0.8×–1.2×，免得 0.7 倍小得点不着。

范围常量定义在 `AppSettings` 里，滑杆的 `Minimum`/`Maximum` 用 `x:Static` 绑同一组值，
设置校验也用它们 —— 两边各写一份的话，手改过 `settings.json` 会出现"滑杆显示一个数、实际用另一个数"。

**拖拽和点击怎么区分**：只看有没有位移，不看按住多久（按住 5 秒不动仍然是点击）。
这条判定比看上去微妙，踩过两个坑：

1. **不能拿"鼠标相对窗口的位置"算位移。** 拖动时窗口跟着鼠标一起走，
   鼠标相对窗口的坐标几乎不变，算出来永远是 0 —— 于是拖多久都被当成点击、直接打开主面板。
   要用屏幕坐标（`Cursor.Position`）或窗口自身的 `Left/Top` 变化。
2. **判定不能在 `OnLeftButtonDown` 里算完等 `OnLeftButtonUp` 来读。**
   `DragMove()` 会进入系统的模态移动循环，`WM_LBUTTONUP` 是在**循环内部**派发的 ——
   WPF 那时就抛出 `MouseLeftButtonUp` 了，比 `DragMove()` 返回还早。任何"事后才写"的标志位
   在 Up 里读到的都是旧值。所以 Up 处理器必须自己独立算一遍。

两个判据取"或"：光标位移超过阈值（5 DIP，会按 DPI 换算），或者窗口真的被挪动过
（后者兜住"拖出去又拖回来"）。拖动时顺手把收起定时器停掉，
所以从状态条上拖拽也不会被误判成"点击收起"。

### 7. 下班提醒
默认 18:00 下班、提前 15 分钟开始提醒，三个渠道同时触发：

1. 小鲸鱼弹一下 + 气泡文案（到点时弹得更高更久）
2. 提示音
3. 系统托盘通知

文案会根据当天状态自动调整语气：一条记录都没有时是催记录，有未收尾事项时提醒标进度，
记录完整但没归档文件时会提示拖文件进来。下班后如果当天仍是空白，会按设定间隔重复提醒。

### 8. 动态素材（小鲸鱼动画）

小鲸鱼能播精灵图动画：单击弹跳、闲置眨眼、到点提醒。素材放在 `Assets\anim\` 下，
一个动作一个子目录：

```
Assets\anim\
  base.png              与精灵图同画布的静态本体
  clickBounce\  sheet.png + sheet.json
  blink\        sheet.png + sheet.json
  alert\        sheet.png + sheet.json      可选
```

规格（画布 720×720、角色 600 高、横向中心 x=360、脚底 y=660）和帧表字段见
**`docs\动态素材规格.md`**；`tools\make_anim_sample.py` 是参考实现，
`tools\check_anim_assets.py` 是交付前校验。实测过容器选型（`tools\animprobe\`）：
只有精灵图 PNG 能同时做到「能播 + 8 位透明 + 不依赖额外组件」，GIF 的透明只有 1 位、
动画 WebP 要装 Store 扩展、APNG 的 WPF 只解第一帧。

播放器是 `Views\SpritePlayer.cs`，两条设计约束值得记住：

- **时间由时钟算，不由"收到几次事件"算。** 每帧显示第几帧是「已过时间 ÷ 单帧时长」。
  渲染时钟约 64Hz，24fps 的动画落在 2~3 个 tick 上，靠计次会累积成明显的忽快忽慢。
- **渲染时钟 + 兜底计时器双通道。** `CompositionTarget.Rendering` 在窗口不可见
  （被隐藏、会话锁定、远程桌面）时根本不触发，只挂它的话动画会永远卡在"正在播放"，
  后面所有动作都被堵住。多挂一个 `DispatcherTimer` 兜底，两个通道都调同一个幂等的 `Advance()`。

素材按需解码：帧表在扫描阶段就解析好（很便宜），真正的位图等第一次播到才解码，
没被用到的动作不占内存。帧是 `CroppedBitmap`，不复制像素。

**换素材最容易砸的一处是显示尺寸。** 画布从 610 变成 720、角色还是 600 高，
如果显示框还留原来的 168px，角色就只剩 140px —— 凭空小 15%，而且肉眼只会觉得"好像小了点"。
所以鲸鱼框高度是按帧表反算的：

```
框高 = 角色的设计屏幕高度(165px) × 帧高 ÷ 角色像素高 = 165 × 720 ÷ 600 = 198px
```

**窗口高度和鲸鱼框必须出自同一个系数**（`ExpandedDesignHeight = 296 + (框高 − 168)`）：
只把图放大不动窗口，多出来的部分会顶掉气泡的位置；只把窗口放大不动图，鲸鱼下方会多一条空白。
实测两次出图确认：装动态素材前后，角色在屏幕上都是 165px，
窗口从 296 变成 326（多出来的 30px 全是画布余量，透明）。

`characterHeight` 没写时算不出框高，程序退回"保持原显示尺寸"——
画面不至于坏，但角色占比会和画的不一致，所以自检里专门有一条断言守着这个换算。

不想让小鲸鱼动：托盘菜单 →「小鲸鱼动画」，素材文件不用删。

#### 8.1 第二条路线：透明视频 + 形象包（2026-09-20 新增）

精灵图那条路要求"画一套帧拼成一张大图"，不适合手上已经有一堆现成动画视频的情况。
出厂自带的「溟月」形象（`Assets\characters\dsh\`，106 个动作）走的是**透明 webm 运行时解码**：

| | 精灵图 PNG | 透明视频（VP9-alpha webm） |
|---|---|---|
| 素材做什么 | 按规格画帧、拼成网格 | 直接给透明视频，**原样搬运、不重编码** |
| 帧表 | `sheet.json` 写清行列/锚点 | `anim.json`，多了 `type: "video"` 和 `filter` |
| 谁来解码 | WPF 自己（`CroppedBitmap` 切帧） | **ffmpeg 子进程**（WPF 解不了 VP9 的 alpha，且必须点名 `libvpx-vp9` —— 见 §8.2） |
| 体积 | 720×720 全量 106 个动作 ≈ **1.4 GB** | 同素材原样 106 个 = **51.9 MB** |
| 依赖 | 无 | 要 `ffmpeg.exe` 在程序目录（便携包已带），缺了只是视频动作播不了 |

解码器 `Services\VideoDecoder.cs` 的 `VideoFrameStream`，几个关键取舍：

- **小环形缓冲（8 帧 = 4.6 MB），不够就卡住生产者。** ffmpeg 解出来的裸 BGRA 帧很占地方
  （384×384×4 = 590 KB/帧），全解到内存里会爆。缓冲满时让它阻塞在写管道上，
  天然不积压，**几乎不吃 CPU**。
- **悬停预热（`SpritePlayer.Warm`）。** 起一次 ffmpeg 要 **≈150 ms**，直接等到点击才起
  会有明显延迟。鼠标移进悬浮窗就先把流起起来、解出前几帧，点下去即时播。
- **时间驱动取帧，一个 tick 最多贴一帧。** 落后了就逐帧追，但**不快进** ——
  跳帧会让 24fps 的动作看起来像抽帧。
- **`filter` 是按不可信输入校验的**（防命令注入）：先按 `=` 切出滤镜名、再按 `:` 切参数，
  位置参数只放行纯数字，具名参数走白名单（`color=black@0`、`flags=lanczos` 等）。

**形象包**（`Services\CharacterPacks.cs`）：一套形象一个目录 `Assets\characters\<形象ID>\`。

```
Assets\
  whale.png                  ← classic（原版鲸鱼娘）的静态本体，**沿用老布局、没搬家**
  anim\                      ← 原版的动作
  characters\
    dsh\                     ← 默认形象「溟月 · 蓝鲸（新版）」
      whale.png  anim\<动作>\{video.webm, anim.json}
      来源与许可.txt          ← 许可要求署名，别删
```

- 设置 →「桌面小鲸鱼」→「形象」里一键切换，**立刻生效、不用重启**
- 往 `characters\` 里再丢一个目录，程序自动发现（可以做自己的形象包）
- 降级顺序 **设置里那个 → `dsh` → `classic`**，永远退得到一个能用的形象；
  `classic` 最后兜底是因为它的图是**编译进程序集的嵌入资源**，`Assets\` 整个不存在也在
- **角色由目录名前缀认**：`idle-` 待机、`clickBounce-` 点击、`ambient-` 随机小动作、
  `drag-` 拖拽、`move-` / `turn-` 保留。**要靠目录名记，不能从动作键反推**
  （`idle` 那支的键历史原因归一化成了 `blink`）

> ⚠️ 这套素材是 CC BY-NC-SA 类同人素材（OC「溟月」/ 画师上善无形），**仅限个人非商业、必须署名**。
> 要发布或商用，`assets\characters\dsh\` 必须整体撤下 —— 撤下后程序会自动退回原版形象。

#### 8.2 踩过的坑：VP9 的 alpha 藏在「附加数据」里（1.4.2 修）

**症状**：形象能播、帧数也对、日志里一个错都不报，但角色**顶着一块黑方块**显示，
边缘像被剪过一样生硬 —— 用户看到的就是"颜色不对、锯齿严重、还有黑底"。

**原因**：透明 webm 的 alpha 不是普通像素，而是 VP9 的**附加数据**
（matroska 的 `BlockAdditional`；`ffmpeg -i` 里能看到 `ALPHA_MODE: 1`）。
ffmpeg 默认挑的 **native vp9 解码器不认这层附加数据** —— 它照样一帧帧给你像素，
只是 alpha 位全填 255。于是透明区成了不透明黑，边缘的羽化也没了。

```bat
-c:v libvpx-vp9        :: 点名解码器之后，像素格式从 yuv420p 变成 yuva420p
```

**代价很小**：同一个动作 241 帧，native 0.155 秒、libvpx 0.183 秒（慢 18%），
而解码本来就跑在实时速度的 60 倍上。

**探测分两步**（`VideoFrameStream.IsVp9Webm` / `FfmpegSupportsVp9Alpha`）：
先读文件头 64 KB 搜明文的 `V_VP9`（不起进程，比每开一个动作就探一次快几个数量级），
再问一次 ffmpeg 有没有这个解码器（问过就缓存）。
两条都满足才加点名参数 —— 否则 mpeg4 之类的素材会因为"解码器不匹配"直接解不开。
本机 ffmpeg 是精简版、没有它时退回 native：至少还能播，只是没透明
（这时 `HasAlpha` 是 false，诊断报告里会写明原因）。

**为什么自检之前没抓住**：当时只断言了"帧数对不对""每帧字节数对不对"，
而这两条在 alpha 全丢的情况下**全都通过**。现在自检里加了一节「透明通道」，
直接**数像素里的透明值** —— 现造一段左半不透明、右半全透明的 VP9 素材，
解一帧出来看有没有 alpha=0 的像素，全 255 就直接判失败。

#### 8.3 踩过的坑：像素字节序红蓝互换（1.4.3 修）

**症状**：黑底是没了，但**颜色整个不对** —— 深蓝紫的头发显示成栗棕红，
眼睛从蓝变橙，用户的原话是"**像反色了一样**"。

**原因**：解码器给的是**裸字节**，没人在中间做转换，所以字节序必须和贴图那边严格对齐：

| 一侧 | 字节序 |
|---|---|
| `-pix_fmt rgba`（改之前） | R, G, B, A |
| WPF `PixelFormats.Bgra32`（`SpritePlayer` 贴图用的） | **B, G, R, A** |

按 `rgba` 吐出来、按 `Bgra32` 贴上去 = 红蓝两条通道整个对调。

**修法**：让 ffmpeg 直接吐 `-pix_fmt bgra`（swscale 内部顺手就换了，**不额外花时间**），
字节序和 WPF 天然对齐，C# 侧一个像素都不用动。

```bat
-pix_fmt bgra          :: 不是 rgba！和 PixelFormats.Bgra32 的内存序对齐
```

实测同一帧：`bgra` 输出按 `B,G,R,A` 解读与 ffmpeg 自己编码的 PNG **逐像素最大差值 0**；
按 `R,G,B,A` 解读则最大差值 125、7.6 万个像素通道不符 —— 这就是"红蓝互换"的量化样子。

**为什么自检两次都没抓住**：这个错**每一帧都一样**，不花屏、不抖动、帧数全对、
每帧字节数也全对。所以 §8.2 补的那节「透明通道」检查（数透明像素个数）
在颜色全反的情况下**照样全过** —— 它只看第 4 个字节。
现在同一节里追加了**通道序断言**：测试素材的左半边是**纯红**，
所以解出来的像素必须满足 `R ≫ B`；红值跑到 B 通道上就直接判失败。

> 这两次是同一个教训的两半：**"解出来了"和"解对了"是两回事。**
> 断言要落在"画面内容"上（透明值多少、红值在哪条通道），
> 而不是落在"流程走通了"（帧数、字节数）上。

### 9. 悬浮时的表情差分

鼠标停在悬浮窗上时，小鲸鱼整张换成另一张形象（默认是闭眼版），移开换回来。

- 素材位 `whale-hover.png`（别名 `closeeye.png`）：外部文件优先，没放就用内置那张
- **必须和主体（`whale.png`）同画布、逐像素对齐。** 差分切换是"整张换掉"，
  画布或位置差一点，鼠标一移上去角色就会跳一下 —— 而这在界面上只表现为"好像抖了一下"，
  极难归因。自检的报告里会把两张图的像素尺寸并排写出来，不一致会直接判失败
- 没放这张图时，悬浮**完全不会**有任何变化（不报错，也不会空一块）
- 和动画的配合（这一段最容易写错）：
  - 正在播动画时切换**不打断**动作，否则会截断成半张脸；
  - **动画播完落回的是"悬浮那张"**，所以悬停期间眨完一次眼不会闪一下睁眼。
    实现上就是让播放器的 `BaseImage` 跟着悬浮状态一起切
- 托盘菜单里没有单独的开关，不想用就删掉素材文件

手里只有一张白底新图也能做：

```bat
python tools\prepare_expression.py 新图.png out\whale-hover.png
```

它会把与四边相连的背景抠成透明、归到基准画布、搜索最佳平移做逐像素对齐，
并报出对齐误差（IoU）和一张差异图：**IoU ≥ 0.98 算合格**，低于 0.95 基本说明
两张图不是同一套画布或同一版形象，别硬用。

一个容易漏的坑：`OnMouseLeave` 里"要不要自动收起"那个分支会**提前 return**，
形象还原必须排在它前面 —— 否则关掉自动收起的用户鼠标一移开，就永远停在闭眼状态。
自检的悬浮探针走的是真实的处理函数，专门守这条顺序。

## 构建

需要在 Windows 10/11 上装 **.NET 8 SDK**。

### 正常环境

```bat
build-whalelog.cmd
```

四步：还原 → 编译 → 发布自包含单文件 → 在桌面创建快捷方式。
产物在 `Publish\WhaleLog.exe`，自包含发布不需要目标机器装 .NET 运行时。

只想编译不发布：

```bat
dotnet build WhaleLog.sln -c Release
```

### 受限环境（restore 报 path1 为空）

如果 `dotnet restore` 报：

```
NuGet.targets(745,5): error : Value cannot be null. (Parameter 'path1')
```

**先试这个 —— 大多数情况到这里就解决了：**

```bat
python tools\mkenv.py        :: 读注册表导出 .tmp-env.sh
```
```bash
source .tmp-env.sh && "C:/Program Files (x86)/dotnet/dotnet.exe" build src/WhaleLog/WhaleLog.csproj -c Release
```

真因往往是**会话里的 `dotnet` 拿不到 Windows 的环境变量**（`ProgramData` / `APPDATA` /
`ALLUSERSPROFILE` 全缺）：NuGet 构造机器级设置时取不到 `CommonApplicationData`（就是那句
`path1`），于是报了这个和项目代码毫无关系的错
（对照实验：PowerShell 5.1 能正常返回 `C:\ProgramData`，.NET 8 返回 null）。
`tools\mkenv.py` 把机器级 + 用户级的环境变量（读注册表）导出成能 `source` 的 shell 脚本，
实测这样编译是 **0 错 0 警**。

**环境变量这条路也走不通时**，才用离线兜底 —— 鲸记不依赖任何 NuGet 包，可以绕过：

```bat
build-whalelog-offline.cmd
```

它会做四件事：

1. 手工生成 `obj\project.assets.json` 等 restore 产物
2. 用 `-p:SkipResolvePackageAssets=true` 等开关编译
3. 手工生成 `WhaleLog.exe`（apphost）
4. 创建桌面快捷方式

第 3 步是必须的：`dotnet WhaleLog.dll` 也能跑，但 `dotnet.exe` 是**控制台子系统**程序，
从快捷方式启动会弹一个黑控制台窗口且全程不消失。`tools/make_apphost.py` 从 SDK 自带的
apphost 模板出发，替换里面的占位符、把子系统改成 GUI、再把鲸鱼图标写进资源段 ——
这三步正是 SDK 在构建时做的事，只是离线环境下得自己来。

## 打包分发

```bat
python tools\make_portable_zip.py            # 输出到 E:\jingji\鲸记 WhaleLog <版本>.zip
python tools\make_portable_zip.py D:\某目录    # 或指定位置
```

产物是**自包含**的：解压到任意目录双击 `WhaleLog.exe` 就能用，
目标机器不需要装 .NET 8（约 135 MB，压缩后 32 位版）。

> **1.4.0 起包大了**：从 58 MB 变成 **139.6 MB**。多了 `Assets\characters\dsh\`
> 的 52 MB 形象素材和 `ffmpeg.exe`（84 MB）—— 两者都是已压缩内容，zip 里压不动。
> 顺手把 `Assets\characters` 也拷了进去，换形象不用自己摆文件。
> 想要小包就删掉包里的 `ffmpeg.exe`：静态形象和精灵图动画照常，只有透明视频动作播不了。
> 找 ffmpeg 的顺序：`WHALELOG_FFMPEG` → `assets\tools\` → PATH → `imageio_ffmpeg`。

正常情况下这件事应该由 `dotnet publish -r win-x86 --self-contained` 完成，
但那需要 NuGet 上的运行时包（`Microsoft.NETCore.App.Runtime.*` /
`Microsoft.WindowsDesktop.App.Runtime.*`）。这台开发机只装了 SDK + 运行时，没有运行时包，
restore 在受限会话里也不可用 —— 所以手工拼：

| 组成 | 说明 |
|---|---|
| 应用本体 | `WhaleLog.dll` + `make_apphost.py` 生成的 `WhaleLog.exe` |
| 宿主解析器 | `hostfxr.dll`（来自 `dotnet\host\fxr\<版本>\`，共享框架目录里没有它） |
| 两个共享框架 | `Microsoft.NETCore.App` + `Microsoft.WindowsDesktop.App` 的全部文件 |
| `runtimeconfig.json` | 用 `includedFrameworks` 声明"框架就在程序目录里" |
| `WhaleLog.deps.json` | 列出全部框架程序集 —— **宿主靠它构造程序集清单** |

两个坑：

- **`deps.json` 不对会直接启动失败**，报 `Could not resolve CoreCLR path`。
  只复制文件、不写清单是不行的。托管 / 原生 DLL 的区分看 PE 头的第 14 个数据目录
  （CLR Runtime Header）是否非 0。
- **两个框架有三个同名程序集**（`WindowsBase.dll` / `System.Drawing.dll` /
  `Microsoft.VisualBasic.dll`），WindowsDesktop 的版本必须覆盖 NETCore 的那个空壳，
  否则 WPF 起不来。脚本按 FrameworkList 的优先级处理。

怎么确认打出来的包是真自包含：自检的「运行环境」会报告运行时位置，
自包含时显示"程序目录内"，框架依赖时显示系统共享目录的路径。
实测时还可以把 `DOTNET_ROOT` 指到一个不存在的路径，能跑起来就说明没用到系统运行时。

## 自测

归档链路（分类、版本判定、指纹、原文件保护）有一份自动化冒烟测试。
它直接编译主程序里与界面无关的那部分源码，测的就是真正发货的代码。

```bat
dotnet build tools\selftest\selftest.csproj -c Release
dotnet tools\selftest\bin\Release\net8.0\WhaleLog.SelfTest.dll
```

覆盖 305 项断言，包括：

- 12 个分类用例，验证「名字命中」要压过「类型兜底」（周报是 .docx，但不该归到「文档」）
- 版本链基名归一化（`v2` / `(3)` / `- 副本` / `第2版` / `_final`，以及叠加后缀）
- 日报与周报：条目统计、分类汇总、版本标注、小结引用、空白日期提示、
  周一到周日的归属换算，以及「生成报告不改动原始记录」
- 端到端归档四轮：首次 → 原样重拖 → 换名同内容 → 真改内容，验证四种判定都不误判
- 跨天再归档：前一天归档过的文件，今天改了内容再归档 → 两天各留一条（前一天 v1、今天 v2），
  同一天里反复改不另起行，快照跟着那一版归档的那天放
  （这条是线上真实报上来的问题：升版本时只改版本号、没动归属日期，
  于是新版本留在旧日期那页，产生它的那天反而空着）
- 归档归属日期：指定日期归档后，那一天能筛到、今天筛不到、「全部」能看到；
  不指定时默认今天
- 按日期分组的排序与栏头文案：日期倒序、同日按拖入时刻倒序、无日期排最后、
  今天/昨天/星期/跨年带年份的写法，以及「行内时间戳必须和栏头同口径」
- 设置校验：越界的浮窗大小 / 不透明度 / 上下班时间会被夹回合法区间，
  取值范围的上下界本身也要合理
- 设置能落盘：**浮窗位置还是 NaN 时也必须存得下去**（见下），以及 NaN 往返之后仍是 NaN
- 外部素材定位：目录不存在、未知素材名、只存在别名文件、主名与别名并存时的优先级、
  素材名大小写不敏感，以及清单自身自洽（名字不重复、候选名必须是纯文件名不能带路径）
- **原文件保护**：归档前后逐字节比对文件内容、修改时间、目录条目数量
- 大文件的采样指纹（同文件稳定、内容变则变、长度变则变）
- 快照模式确实产出可读的副本，且原文件仍在原地
- 动态素材（精灵图）：帧表字段校验与 8 类报错原因、能救回的 6 类、
  **行优先**切帧的坐标、动作名归一化与别名、目录扫描（含同名撞车时"目录名即动作键"者优先）
- 动态素材（透明视频）：`filter` 的**分隔符解析与注入拦截**（先按 `=` 切滤镜名再按 `:` 切参数 ——
  顺序反了会把 `crop=384:360:128:0` 的**名字**切成 `crop=384`，把 106 个动作全判成非法）、
  非法参数被拒、真起一次 ffmpeg **解非循环流与循环流**
- **透明视频解出来的像素内容**（见 §8.2 / §8.3）：现造一段「左半不透明纯红、右半全透明」的
  VP9 素材，解一帧出来**直接验像素** —— alpha 有没有真透明值（`0` 与 `255` 各占一半）、
  红值有没有落在 R 通道上（红蓝互换时红会跑进 B 通道）。这两条都是"帧数全对、字节数全对、
  一个错都不报"的那类故障，只有验内容才拦得住
- 形象包：发现 / 可用性 / 降级三级（设置里那个 → `dsh` → `classic`）、
  越权路径（ID 里塞 `..\`）不越出素材目录、自建形象包能被发现
- 角色识别：按**目录名前缀**归类（`idle-` / `clickBounce-` / `ambient-` / `drag-` / `move-` / `turn-`），
  以及哪些角色是循环播放

加 `--keep` 参数可以保留临时目录，方便翻看产出的 Markdown 和 index.json。

> ⚠️ 自测里含「真的起一次 ffmpeg 解一遍视频」的用例。跑之前把 ffmpeg 拷到
> `tools\selftest\bin\Release\net8.0\ffmpeg.exe`（`FfmpegLocator` 找的第一个位置就是程序目录）。

## 数据存放

默认在 `%AppData%\WhaleLog\`。程序目录下放一个 `portable.txt` 就切换成便携模式，
数据改存到程序目录的 `data\` 下。

```
%AppData%\WhaleLog\
├── settings.json          用户设置
├── index.json             结构化索引（记录条目 + 文件记录 + 版本链）
├── index.json.backup      上一版索引，损坏时自动回滚
├── rules.json             分类规则，可以直接编辑
├── notes\
│   └── 2026-09-11.md      每日笔记，人可读，可以直接进 Git
├── archive\               归档快照（仅在开启快照模式时产生）
└── logs\
    └── error.log          未处理异常日志
```

写盘一律「先写 .tmp 再替换」，避免异常退出留下半截文件。

## 分类规则

`rules.json` 是一个数组，每条规则 = 筛选条件，借鉴 DropIt 的协议模型但砍掉了「动作」那一半
（鲸记的动作永远是「记一笔」）：

```json
{
  "name": "汇报与总结",
  "category": "汇报材料",
  "priority": 10,
  "enabled": true,
  "extensions": [".docx", ".pptx", ".pdf"],
  "nameKeywords": ["周报", "日报", "总结"],
  "pathKeywords": []
}
```

匹配语义：

- 一条规则里配了多个维度就是**与**关系，全部满足才算命中
- 规则之间按 `priority` 升序**或**匹配，第一个命中的就是结果
- 三个维度都留空 = 匹配所有文件（别这么写）

所以「名字含周报的文档」这类精确规则要排在「所有表格文件」这类兜底规则前面。
内置默认规则（可在设置页一键恢复）：汇报材料 10 → 合同协议 15 → 会议材料 20 → 设计稿 25 →
需求方案 30 → 表格数据 40 → 演示文稿 45 → 文档 50 → 代码 60 → 图片 70 → 压缩包 80 →
音视频 85 → 安装包 90 → 数据与日志 95 → 未分类。

## 图标

`tools/make_icon.py` 把 610×610 的 `DSniang1.png` 转成 7 个尺寸的 `whalelog.ico`
（16/24/32/48/64/128/256）。16–32 像素用头部特写，48 以上用全身像——全身像缩到 16 像素会糊成一团。

ICO 条目统一写成 32bpp DIB（BITMAPINFOHEADER + BGRA 位图 + AND 掩码），
兼容性比 PNG 内嵌条目好。

重新生成：

```bash
python tools/make_icon.py
```

程序目录下放一个 `whalelog.ico` 会优先使用它，所以想换图标不用重新编译。

## 外部素材

程序旁边的 `Assets\` 目录里放着当前用的小鲸鱼图和图标。把同名文件放进去就会**优先于**
编译进程序的内置素材，换形象不用重新编译。

```
WhaleLog.exe 旁边
└── Assets/
    ├── whale.png          桌面小鲸鱼形象（也认 DSniang1.png、anim\base.png）
    ├── whale-hover.png    鼠标悬浮时的形象（也认 closeeye.png），必须与 whale.png 同画布
    ├── whale-head.png     小头像（也认 head.png）
    ├── whalelog.ico       程序与托盘图标（也认 app.ico）
    ├── whalelog-256.png   关于页预览图（也认 preview.png）
    ├── anim/              动态素材，一个动作一个子目录（见「8. 动态素材」）
    │   ├── base.png       与精灵图同画布的静态本体
    │   └── clickBounce\   sheet.png + sheet.json
    └── 素材说明.txt       每个文件的规格，程序自己生成
```

`whale.png` 和 `whale-hover.png` 是**同一套形象的两张差分**，所以画布和角色位置必须逐像素一致
（详见「9. 悬浮时的表情差分」）。

首次运行时程序会把内置素材导出到这个目录 —— 用户打开就能看到该换哪个文件，
而不是对着一份文档猜文件名。**已存在的文件一概不覆盖**，所以自己换过之后不会被程序冲掉；
删掉某个文件就恢复成内置默认。

换完在托盘图标上点右键 →「重新加载素材」，悬浮窗和主面板立刻刷新；
`whalelog.ico` 需要重启程序（资源管理器缓存了图标）。

几个刻意的设计：

- **外部文件读不出来就安静回落到内置**，并在 `error.log` 留一条记录。静默回落最坏的结果是
  用户以为"我那张图生效了"，其实看到的是内置图。
- **加载时立刻读完并释放文件句柄**（`BitmapCacheOption.OnLoad`），否则素材文件会被程序占住，
  用户想替换时得到"文件正在使用中"。
- **无视 WPF 按 URI 的图片缓存**（`IgnoreImageCache`），否则改了文件内容界面上还是旧图。
- **只有明显大于显示尺寸的图才限制解码高度**。悬浮窗最大显示约 270px，一张 4000×4000 的图
  不限制解码会白占几十 MB 内存；小图不限制 —— 否则会被插值放大再缩回去，白白变模糊。
- 目录可以用环境变量 `WHALELOG_ASSET_DIR` 指向别处（隔离测试，或把素材集中放在一个共享目录）。

XAML 里不写 `pack://` URI，而是 `Source="{v:AssetImage whale-head}"` ——
直接写 URI 会绕过上面这套解析，用户在 `Assets\` 里换的图就不生效。

自检报告里会写清楚每个素材**实际生效的来源**：

```
whale.png            外部 whale.png（生效）
whale-head.png       外部文件读不出来，已回落内置（whale-head.png）
whalelog.ico         内置默认
```

这里刻意区分"磁盘上有没有外部文件"和"实际用的是哪个"——文件存在但读不出来时，
界面上用的是内置图，报告还写"外部"就是误导。

打包脚本会把出厂素材一起放进压缩包（内部调 `--export-assets`），用户解压后立刻能看到这个目录。

## 诊断自检

有些环节是"点一下才知道好不好"的——全局快捷键能不能注册、托盘图标能不能加载、
快捷方式能不能创建、每个窗口能不能正常打开、页签切换会不会同时显示两页、
月历的网格有没有错位、文件筛选点了会不会真的变、日期栏头有没有真的渲染出来。
自检把它们挨个跑一遍并写结论：

```bat
WhaleLog.exe --selfcheck
```

结果写到 `%AppData%\WhaleLog\logs\selfcheck.log`。加 `--quiet` 只写日志不弹窗（给脚本用）。

这个命令在开发时也很有用：WPF 里"资源键写错""把画刷当样式用""事件在 XAML 解析阶段就被触发"
这类问题编译期一个都不报，只有真的把窗口创建出来才会暴露。自检里的"窗口创建"和"页签互斥"
两节就是为此存在的。

「文件筛选」那一节验的是同一类错误的另一个实例：筛选状态曾经读的是**另一个**胶囊的
`IsChecked`，于是点「只看当天」时状态根本不翻转、界面毫无反应——而它编译通过、
窗口也正常打开。断言按 ToggleButton 的真实点击行为（先翻转 `IsChecked` 再抛 `Click`）
逐条走：切到全部、切回当天、重复点当前胶囊、来回切三次，每一步都要求
"恰好一个被选中"且列表条数和存储层的查询结果一致。

月历那一节验的是几何：以周一为第一列时，2026-09-01 是周二，网格左上角必须是 2026-08-31。
这类偏移算错一位，整月日期会全部错位，而界面看上去完全"正常"——只有断言能抓住。
同一节还覆盖了「跳到」输入框的日期解析：各种分隔符写法、跨年回退、闰年与无效日期、
未来日期拒绝、只填日号落在哪个年月。这些分支在界面上极难逐一试到。

「文件日期分组」那一节除了断言分组数量、次序和条数总和，还会去**可视树里数一数真的有几个
栏头**——有分组对象不等于 `GroupStyle` 生效了，更不等于栏头里的文字看得见。所以还要求每个
栏头的标题有真实宽高（宽度塌成 0 就是"有栏头但空白"）。

「滑杆」那一节验的是拖动链路：`Thumb` 有没有被别的元素盖住（拿手柄中心做命中测试）、
`PART_Track` 宽度是不是 0、然后**真的抛一次 `Thumb.DragDelta`**，看值变没变、
界面读数有没有跟着更新、`_syncing` 守卫有没有释放。拖动没反应时，界面上完全看不出是哪一环断的。

「悬浮窗缩放」那一节量的是实际排布：内容底边有没有越过窗口底边（裁切）、
鲸鱼渲染高度是不是等比。注意**不能读 `ActualHeight`** —— `LayoutTransform` 作用在元素外面，
`ActualHeight` 仍然是变换前的布局尺寸（永远报 168），要 `TranslatePoint` 量变换后的实际高度。
另外探针必须先把「不用时收起」关掉：开着的话窗口一加载就把自己收成小胶囊，
后面量到的宽高全是收起态的（48px），和展开态的期望值对不上。

还有一点容易踩：悬浮窗的 `ClampToArea()` 会把任何越界的位置**强行拉回工作区**，
所以"把探针窗口摆到 -32000"实际会停在桌面左上角 —— 每次跑自检都闪一下、还会抢焦点。
探针要显式打开 `BackgroundProbeMode` 跳过这个约束，并且 `ShowActivated = false`。
这一条本身也有断言（"探针窗口落在屏幕外"），别指望目测。

「今日记录里的归档文件」那一节把需求直接写成断言：两处列表必须是**同一个模板对象**
（`ReferenceEquals`，这才是"样式保持一致"）、相邻卡片的矩形不能相交、还得留下间距。
量的是**卡片本身**而不是 ItemsControl 的容器 —— 卡片自带的下外边距落在容器内部，
量容器的话相邻两张永远严丝合缝地贴着，看不出"到底有没有留间距"。

### 界面截图

有些东西断言不了，只能看：文字有没有被裁、某个主题下颜色是不是糊了、对齐歪没歪。
`--shot` 渲染「文件归档」页（「全部」筛选，能看到跨天分组），`--shot-notes` 渲染
今日记录页（当天的事项和归档文件），`--shot-settings` 渲染设置页（各项开关、滑杆、
形象那一排按钮都在这一页 —— "按钮该亮还是该灰"这种事只能看图确认），`--shot-floating`
把悬浮窗在最小 / 默认 / 最大三档下渲染成一张对照图。都是离屏渲染，不会弹到面前：

```bat
WhaleLog.exe --shot D:\tmp\files-page.png
WhaleLog.exe --shot-notes D:\tmp\notes-page.png
WhaleLog.exe --shot-settings D:\tmp\settings-page.png
WhaleLog.exe --shot-floating D:\tmp\floating-scales.png
WhaleLog.exe --export-assets D:\tmp\Assets      :: 只导出出厂素材，不启界面
```

配合 `WHALELOG_DATA_DIR` 指向一份造好的临时数据，就能在没有合适真实数据时也看到跨多天的
分组效果，而不用往自己的记录里塞测试文件。`WHALELOG_ASSET_DIR` 同理，用来隔离素材目录。

> 悬浮窗的截图刻意**不用抓屏**：多显示器可能是负坐标、还有 DPI 缩放，
> 抓屏量出来的尺寸和窗口真实尺寸对不上，反而误导。离屏渲染是确定性的。

### 鼠标交互的实测探针

悬浮窗的"拖拽还是点击"没法靠断言测：`DragMove()` 是阻塞式的、会进入系统的模态移动循环，
只有真实的按下-移动-松开才能走到那条路径。所以用 Win32 合成真实鼠标输入来验：

```bat
python tools\drag_probe.py
```

它会启停三次程序（用临时数据目录，不碰你的配置），分别验证：

| 场景 | 期望 |
|---|---|
| 拖 240×160 像素 | 窗口移动，**主面板不出现** |
| 原地按下松开 | **主面板出现**（这是点击） |
| 从状态条区域拖拽 | 主面板不出现，**且窗口仍是展开态**（没被当成"点击收起"） |

代价是它会真的移动你的鼠标光标、并且会先结束正在运行的鲸记（单实例限制），
所以是手动运行的，不进自检。拖拽判定改过之后记得跑一次。

三点说明：

- **可以在程序运行时执行，而且完全没有副作用。** 自检属于一次性命令，不参与单实例互斥 ——
  否则想跑个自检会先被"鲸记已经在运行了"拦下来，日志却毫无变化，很难排查。
  这种情况下全局快捷键必然抢不到（被正在运行的那个实例持有），
  自检会识别出来并标注为正常，而不是误报成故障。
- **自检不会动你桌面上的快捷方式。** 「创建快捷方式」这一项是在
  `logs\shortcut-probe\` 里试创建的，验证完就删掉。（早期版本直接打桌面，
  于是"从解压出来的副本跑一次自检"就把快捷方式改指到了那个临时目录，副本一删它就废了。）
  自检同时会**报告**桌面快捷方式当前指向哪个 exe，指向的文件不存在时会提示重建。
- **自检绝不会改动你的配置。** 探针为了验证界面会去改内存里的设置对象（比如临时把浮窗
  缩放到 1.6 来量有没有被裁），而退出时 `SettingsService.Save()` 会把这个对象整个写回
  `settings.json` —— 探针的改动就这样"泄漏"进用户配置了（真出过：不透明度被写成 1）。
  现在 `RunReport` 和 `WriteFloatingShot` 都在开始时留一份设置快照、结束时整体恢复，
  不管探针怎么改、甚至中途抛异常都能兜住。

## 已知边界

- **不移动原文件**。如果原文件被移走或删掉，记录里会标注「文件已不在原位置」，
  但记录本身保留，方便回头查它当时叫什么、在哪儿。
- **采样指纹有理论漏判**。超过阈值的文件用采样比对，理论上极小概率把"改了但改动落在未采样区间"
  的文件判成没变。把设置里的阈值调大可以改成全量比对，代价是慢。
- **悬浮窗贴边用的是当前显示器的工作区**，多显示器且各屏缩放比例不同时，
  收起/展开的锚定边偶尔会有几像素偏移。
- 规则引擎只做分类，**不做按规则移动文件**。这条是有意为之，见上文的数据安全说明。
- 设置文件里 `floatingLeft` / `floatingTop` 可能是 `"NaN"` 字符串 —— 那表示
  "还没保存过悬浮窗位置"，不是坏值。JSON 规范里没有 NaN 字面量，所以只能写成字符串；
  序列化时必须开 `AllowNamedFloatingPointLiterals`，否则写不出去。手改这个文件时按原样留 `"NaN"` 就好。
- 命令行开关既支持 `--shot 路径` 也支持 `--shot=路径`。只做全等比较的话，
  带等号的写法会被当成"没有这个开关"，程序就按普通方式启动 —— 不退出、一直开着，
  命令行那边只能看到"卡住"。
