## 六、查「为什么连不上 github」（17:42–17:50）—— 结论：网络是通的，错在凭据

用户问「为什么连不上」。实测逐层拆开，**推翻了旧记录里"本机连不上 github.com、被代理拦 502"这条**：

| 层 | 实测结果 |
|---|---|
| DNS | `github.com` → 20.205.243.166，`api.github.com` → 20.205.243.168，正常 |
| TCP 443 | 直连 IP 可连接 |
| HTTPS 直连 | `curl --noproxy '*' https://github.com/` → **200，1.17 s** |
| 走环境代理 | 同一个 URL 走 `HTTPS_PROXY=127.0.0.1:5574` → **12 s 超时**，只收到 563,104 字节后断流 |
| git 协议 | `git ls-remote <repo>` → **exit 0**，说明连上了 GitHub 并拿到了应答 |
| push | `fatal: could not read Username for 'https://github.com': terminal prompts disabled` |

三条真因：

1. **没有可用凭据**（主因）。`credential.helper = helper-selector`（local 配置）想弹 GUI 选凭据，
   非交互环境弹不出来 → 一直挂到超时。这就是"连不上"的体感来源：**能连上，但 push 卡死**。
   `GIT_TERMINAL_PROMPT=0` 也拦不住 helper-selector，实测两次都挂满 30 s 被 `timeout` 杀掉（exit 124）。
2. **远端仓库是空的**：`.../whalelog.git/info/refs?service=git-upload-pack` → 200 / 366 字节，
   body 里只有 `# service=git-upload-pack` + capabilities，**零个 ref**。仓库网页 200、用户页 200
   → **公开、存在、但一个 commit 都没有**（从来没 push 成功过）。这与"只能本地 commit"完全吻合。
   ⚠️ 旧记录写"私有"是错的：私有仓匿名访问不会返回 200。
3. **环境里注入的坏代理**：`HTTP_PROXY/HTTPS_PROXY=http://127.0.0.1:5574`（WorkBuddy 沙箱），
   对 github.com 会传一半断流。git 会读这两个变量 → 大流量操作（clone/拉素材）会被它拖死。
   **跑 git 前先 `env -u https_proxy -u HTTPS_PROXY -u http_proxy -u HTTP_PROXY`。**
   注意 git 配置里 `http.proxy` 是空的，所以元凶是**环境变量**不是 git 配置。

要真推上去需要两步：① 剥掉代理环境变量；② 配一个 PAT（`git remote set-url origin https://<PAT>@github.com/...`
或 `git config --global credential.helper store` + 首次输入），然后把 `master` 改名 `main` 推。
**没擅自改用户 git 全局配置，等用户给 token。**
