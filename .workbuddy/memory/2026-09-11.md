- 新增 `tools/make_icon.py`：610×610 PNG → 7 尺寸 ICO（小尺寸走头部特写，

- 新增 `tools/selftest/`：76 项断言的归档链路冒烟测试，直接编译主程序里

### 实跑抓到的三个真实 bug（只编译不运行是发现不了的）

1. `Style="{StaticResource TextMutedBrush}"` —— 把画刷当成样式用，运行时
   `XamlParseException`。编译期完全不报错。
2. Slider 的 `ValueChanged` 写在 XAML 里，解析阶段 `Minimum` 赋值会强制转换

   加 `UnsafeRelaxedJsonEscaping` 修掉。
4. 归档没有把当天 `DayNote` 登记进去，导致每日 Markdown 不生成、文件清单缺失。

## 环境问题：这台机器上 NuGet restore 不可用

`dotnet restore` 稳定报：

```
NuGet.targets(745,5): error : Value cannot be null. (Parameter 'path1')
```

根因：NuGet 构造 `XPlatMachineWideSetting` 时调用
`Environment.GetFolderPath(CommonApplicationData, DoNotVerify)`，在这个受限会话里
返回 **null**（`PROGRAMDATA`/`APPDATA` 环境变量在宿主进程里就是空的，
而且即使 `export` 出去 .NET 也拿不到）。对照实验：
PowerShell 5.1（.NET Framework）能正确返回 `C:\ProgramData`，.NET 8 返回 null。

绕过办法（`tools/offline_restore.py` + `build-whalelog-offline.cmd`）：

1. 手写 `obj/project.assets.json`、`<项目>.csproj.nuget.g.props/.g.targets`、
   `<项目>.csproj.nuget.dgspec.json`（WPF 的 XAML 编译步骤会复制 dgspec）。
2. `dotnet build --no-restore -p:SkipResolvePackageAssets=true
   -p:GenerateDependencyFile=false -p:GenerateRuntimeConfigurationFiles=false`
   —— 这三个开关都能在 SDK 的 targets 文件里找到对应的 Condition 门。
3. 补 `runtimeconfig.json` + `deps.json` 才能 `dotnet Xxx.dll` 启动。

另外两个坑：

- **TFM 不要带 OS 版本号**。`net8.0-windows10.0.19041.0` 会要求
  `Microsoft.Windows.SDK.NET.Ref`，那是需要 restore 的包。项目不碰 WinRT 投影
  就用 `net8.0-windows`，少一个依赖。
- **不要设 `PlatformTarget=x64`**。这台机器上 `dotnet.exe` 在
  `C:\Program Files (x86)\` 下、是 32 位宿主，加载 x64 程序集会
  `FileLoadException: Could not load file or assembly`。用 AnyCPU。
- `UseWPF` + `UseWindowsForms` 同时开时会有大量类型名歧义
  （`Application`、`Point`、`MouseEventArgs`、`DragEventArgs`、`IDataObject`），
  用 `<Using Remove="System.Windows.Forms" /><Using Remove="System.Drawing" />`
  去掉隐式 using，需要的地方各自显式 using。

## 第二批：全局快捷键、日报周报、桌面快捷方式

### 离线生成 apphost（`tools/make_apphost.py`）

`dotnet WhaleLog.dll` 能跑，但 `dotnet.exe` 是**控制台子系统**程序，
从快捷方式启动会弹一个黑控制台窗口且全程不消失。所以需要真正的 `WhaleLog.exe`。

SDK 生成 apphost 要 NuGet 还原，这里手工做，三步：

1. 替换占位符。**关键坑：同一个占位符在二进制里有多个副本**
   （`.rdata` 里还有一处把两个占位符连写成 64 字节的版本），
   只替换 `.find()` 找到的第一处，宿主仍然会读到没被替换的那份，报
   `The application to execute does not exist: <占位符原样>`。必须循环替换全部。
   槽位长度 = 占位符本身 + 紧随其后的连续 0，补 0 只覆盖本来就是 0 的填充位。
2. 改 PE 可选头的 Subsystem：3（控制台）→ 2（GUI）。偏移 = `e_lfanew + 4 + 20 + 68`。
3. 用 `BeginUpdateResourceW` / `UpdateResourceW` / `EndUpdateResourceW` 注入图标：
   每张图进 `RT_ICON`（ID 从 1 开始），再写一个 `RT_GROUP_ICON`（ID 1，
   GRPICONDIR + GRPICONDIRENTRY[]）。

**架构要按本机已安装的运行时选**：这里只有 x86 运行时
（`C:\Program Files (x86)\dotnet\host\fxr`），用 win-x64 的 apphost 直接启动失败。

### 桌面快捷方式必须由程序自己创建

`build-whalelog.cmd` 里不要用 PowerShell 拼中文快捷方式名 ——
`.cmd` 的中文编码很容易踩坑。改成程序里加一个 `--create-shortcut` 命令行开关，
脚本只调 `WhaleLog.exe --create-shortcut --quiet`。

创建用 `WScript.Shell` COM（反射后期绑定，不用引 Interop 程序集）。
桌面路径要用 `SpecialFolders("Desktop")`，**不能拼 `%USERPROFILE%\Desktop`** ——
桌面被 OneDrive 重定向或换系统语言时只有它拿得到真实路径。
`Environment.GetFolderPath(DesktopDirectory)` 在这台机器上同样返回空。

### 又一次实跑抓到的 WPF 缺陷

`OnDeactivated → Close()` 会重入：`Close()` 过程中窗口失活，失活又回调 `Close()`，
WPF 抛「在窗口关闭期间无法调用 Close」。异常被全局处理器吞掉，表面上正常，
但错误日志一直堆栈。修法：统一走带 `_closing` 守卫的 `RequestClose()`。
`QuickCaptureWindow`（失焦自动收起）和 `TrayMenuWindow`（失焦自动关菜单）都中招。

### 新增：诊断自检 `--selfcheck`

有些环节"点一下才知道好不好"：快捷键能否注册、托盘图标能否加载、快捷方式能否创建、
每个窗口能否正常创建。自检挨个跑一遍写 `logs\selfcheck.log`，`--quiet` 不弹窗。
开发期价值很大 —— 上面那个 Close 重入缺陷就是自检的"窗口创建"一节抓出来的。

新增日报/周报断言：条目统计、分类汇总、版本标注、小结引用、空白日期提示、
周一到周日归属换算、以及"生成报告不改动原始记录"。

## 第三批：用户报的 UI 重叠 bug

### 症状与根因

用户报"今日记录和文件归档同时点开会有 UI 重叠"。

根因在主面板的页签逻辑：三个页面的可见性是**各读各的 `ToggleButton.IsChecked`**：

```csharp
PageNotes.Visibility = NavNotes.IsChecked == true ? Visible : Collapsed;   // ← 错在这
```

而 WPF 的 `ToggleButton` 之间**不会互斥** —— 点「文件归档」后 `NavNotes` 仍然是勾选状态，
于是两个页面都被设成 `Visible`。而这三个页面本来就叠在同一个 Grid 单元格里
（靠切换 Visibility 来"翻页"），所以直接完全重叠。

更讽刺的是末尾那段"禁止把当前页签也点掉"的兜底：因为 `NavNotes` 一直勾选着，
它的条件永远不成立，等于完全没起作用。

修法：引入 `_activePage` 作为唯一的 source of truth，三个页面的可见性和三个
ToggleButton 的勾选状态**全部从一个值推导**，不再互相读取。
另外兜住"再点一次当前页签会导致 IsChecked 被反选成 false"的情况（此时维持当前页）。

### 顺带修掉的两个问题

1. **`--selfcheck` / `--create-shortcut` 被单实例守卫挡掉。** 程序正在运行时想跑一次
   自检，会先弹"鲸记已经在运行了"然后什么都不做，日志毫无变化 —— 排查时会以为是
   自检本身坏了。改成：一次性命令不参与互斥（它们不是"又开了一个鲸记"），
   同时跳过 `EnsureToday()`，避免和正在运行的实例同时写 index.json。
2. **自检误报快捷键失败。** 允许在运行时自检之后，全局快捷键必然抢不到
   （被正在运行的那个实例持有）。加了 `App.IsAnotherInstanceRunning()`
   （`Mutex.TryOpenExisting`），识别出这种情况就标注为正常，不报成故障。

### 又加了一节自检：页签互斥

用 `FindName("NavFiles")` 拿到按钮，按 ToggleButton 的真实行为模拟点击
（先翻转 `IsChecked` 再 `RaiseEvent(ButtonBase.ClickEvent)`），逐个页签验证
`VisiblePageCount == 1`，并覆盖"重复点当前页签"的边界。

这个 bug 只靠编译和"窗口能创建"是抓不到的 —— 必须真的去点。
以后凡是"多个控件叠在同一个单元格靠 Visibility 翻页"的写法，都要有这类断言。

## 第四批：日期栏展开整月日历

### 需求

用户要"点击日期栏生成二级菜单显示整个月，便于快速切换回溯"。

### 实现

新增 `Views/MonthCalendarPanel.xaml(.cs)`（UserControl），挂在 MainWindow 日期栏的
`Popup` 里（`StaysOpen=False`，点外面自动收）。

- 固定 **6 行 × 7 列 = 42 格**：有的月份 5 行就够，但恒定 6 行能让面板高度不跳。
- 以**周一为第一列**（中文习惯）：网格起点 = `month.AddDays(-(((int)month.DayOfWeek + 6) % 7))`。
- 三个信息维度叠在一个格子：月份归属（非本月变淡但仍可点）、今天（强调色描边）、
  有记录（数字下方一个小圆点）。圆点数据来自"当天有条目 OR 当天有归档文件"。
- 未来的日期 `IsEnabled=false`，未来的月份也不允许翻（`NextMonthButton` 置灰），
  和日期栏「›」的既有规则保持一致。
- 选中走 `Pick(date)`，日期格点击和程序调用是同一条路径 → 抛 `DateChosen`。

### 两个 WPF 细节

1. **`Popup` + `StaysOpen=False` 会吃掉触发按钮自身的点击**：点日期栏时弹层先自己关掉，
   那次点击不会再走到 `Click`，"再点一次收起"就永远失效。用 `Closed` 时间戳 +
   260ms 时间窗识别"刚关掉"的情况。
2. **主题色用 `SetResourceReference` 而不是直接赋 Brush**，这样切主题时能跟着换，
   不用等面板下次重建。动态生成的日历格子没有 XAML 可以写 `DynamicResource`。

### 自检又扩了一节（月历 15 项）

网格几何是最值得断言的地方：偏移算错一位，整月日期全部错位，但界面"看起来正常"。
断言了 42 格、起点是 2026-08-31（周一）、42 天连续无重复、当月每天恰好出现一次、
翻月后仍从周一开始、标记数正确、未来日期不可选、未来月份不可翻。

### 顺带修掉一个反复踩的编译坑

探针方法的断言回调参数类型原来是 `Action<string, bool, string>` ——
`Action` **不支持可选参数**，所以在探针里写 `check("标题", true)` 会编译不过，
只能到处补一个多余的 `""`。这已经踩了三次。改成自定义委托：

```csharp
private delegate void CheckFn(string name, bool ok, string detail = "");
```

以后新增探针不会再遇到这个问题。

### 关于"改代码要重启程序"

这轮又遇到两次 `MSB3021/MSB3027：文件被 WhaleLog (PID) 锁定` —— 用户正开着程序，
Release 的 dll 没法覆盖。合理做法：**先在 Debug 版上把功能验证完（不同目录，不会冲突），
最后只做一次切换**（关掉 → 重建 Release → 重生成 apphost → 重指快捷方式）。
别在每个中间步骤都去动 Release。

## 第五批：「跳到」输入框（按日期快速跳转）

### 实现

月历面板底部加了「跳到」输入框，`MonthCalendarPanel.TryParseJump` 是纯函数，
支持：`9/23`　`9-23`　`9.23`　`0923`　`2026-09-23`　`2026/9/23`　`20260923`
　　`9月23日`　`9月23号`　`2026年9月23日`　`今天/昨天/前天/大前天`　只填日号（当月）

两个设计决定：

1. **只写月日、今年那天还没到时，按去年同一天理解。** 这是往回翻日志的工具，
   九月里敲「12/25」显然不是想跳到三个月后。但这个行为必须**可见** ——
   所以输入框旁边边打字边显示解析结果（`→ 2025-12-25 周四`），
   用户一眼就能看出自己敲的会被理解成哪天。
2. 打开面板时把键盘焦点放进输入框，敲完 Enter 就走。顺带解决了
   **Popup 有自己的 HWND，键盘事件不一定穿过宿主 Window 的 PreviewKeyDown** ——
   给面板加了 `DismissRequested` 事件让宿主关弹出层，不再只依赖 Window 级 Esc。

### 自检又加了一节（日期解析 35 项）

纯逻辑分支在界面上极难试全：各种分隔符、中文写法、紧凑 8 位、跨年回退、
闰年与无效日期（`2/30`）、未来拒绝、只填日号落在哪个年月。断言里用
`DateTime.Today` 动态算期望值，保证一年四季跑都成立。

### 又一个命名坑

面板里有个私有方法 `Key(DateTime)`，和 `System.Windows.Input.Key` 枚举撞名，
导致写 `Key.Enter` 编译不过（CS0119）。改名为 `DateKey`。
教训：**给方法起名别用 BCL 里常见的类型名**（Key / Point / Color / Brush / Path / Task）。

## 修复：文件归档「只看当天」点了没反应

用户报障。查下来是**两个**独立问题叠在一起：

1. **筛选状态读的是"另一个"胶囊。** `_showAllFiles = FileFilterAll.IsChecked == true;`
   —— 点「只看当天」时那个胶囊还留着上次的勾选，条件没变，界面毫无反应。
   和之前页签重叠是同源缺陷，**上一轮我判错了**：我说过"文件筛选是以被点的那个为准、
   没有这个问题"，实际并没有扫到这一处。教训：不要靠"看着像没错"下结论，要 grep。
   修法与页签一致：单一 source of truth `_showAllFiles` + `SetFileFilter(bool)`，
   目标值由被点的 sender 推导，再点当前项时维持原值（否则两个都不选）。
2. **归属日期跟着"当前查看日期"走，但界面没说。** 用户 15:26 拖的
   `DLJ_ALL_action_autosave3.blend`（283MB，采样指纹）当时被记到了 9/7 ——
   因为那次拖拽时窗口停在 9/7。回到今天，"只看当天"当然什么都看不到，
   于是看起来像"这个按钮坏了"。规则本身合理（支持补录过去某天），
   但横幅必须写明目标日期，所以 `DropBannerTitle/Hint` 改成动态的。

顺带：胶囊文案「只看今天」→「只看当天」，因为它跟着 `_currentDate` 走；
空列表提示也带上日期，并提示可以切「全部」看历史。

### 自检/自测都补了

- 诊断新增「文件筛选」一节 13 项：按 ToggleButton 真实点击行为逐条走
  （切全部 → 切回当天 → 重复点当前项 → 来回切三次），每步都要求
  "恰好一个被选中"且列表条数与存储层查询结果一致；外加横幅文案在
  今天视图 / 历史视图下的断言。自检总数 81 → 94。
- 自测新增「归档归属日期」6 项：指定日期归档后那一天能筛到、今天筛不到、
  「全部」能看到；不传日期时默认今天。总数 109 → 115。

## 新增：文件归档「全部」视图按日期分组

用户要求：全部视图里每个文件标出归档日期，同一天的文件收在一个日期栏下，栏间按日期排。

- 新增 `Services/DateGrouping.cs`（放非界面代码里，好让自测直接断言）：
  `Sort()` 日期倒序 → 同日按 `AddedAt` 倒序 → 文件名兜底保证稳定；
  `Label()` 出「今天 · 9月11日」「昨天 · …」「周三 · 9月7日」，
  跨年带年份（不写年份的话"9月7日"是哪年看不出来），空日期 → 「未标注日期」。
- 分组用 `CollectionViewSource.GetDefaultView(_files).GroupDescriptions`
  + XAML `ItemsControl.GroupStyle`（`HeaderTemplate` 绑 `{Binding Name}` 过转换器）。
  只在「全部」视图挂 `PropertyGroupDescription`；「只看当天」同一天，加栏头是噪音。
- **分组的先后取决于记录在集合里的出现顺序**，所以 `RefreshFileList` 里必须先排好序，
  不能指望 ObservableCollection 自己有序。
- 行内时间戳改用 `AddedStampText`（归属日期 + 拖入时刻），并删掉原来只显示时刻的
  `AddedTimeText` —— 两个口径并存早晚会出现"栏头写 9月7日、行里写 9月11日"。
- 统计行改成「共 4 天 6 个 · 分类…」。

### 新增 `--shot`：把界面渲染成 PNG

有些东西断言不了，只能看：文字被裁、某主题下颜色糊、对齐歪。`--shot <路径>` 用
离屏窗口（-32000,-32000）把「文件归档」页在「全部」筛选下 `RenderTargetBitmap` 成 PNG，
不会弹到用户面前。配合 `WHALELOG_DATA_DIR` 指向临时数据目录，就能在没有合适真实数据时
也看到跨多天分组效果 —— 不用往用户自己的记录里塞测试文件。

**当模型看不了图片时，图像分析不可靠**（我先按"整行主导色"猜色带，卡片和栏头都是
全宽底色，分不出来）。更硬的办法是断言**可视树**：数 `GroupItem` 的个数、
要求栏头标题 `ActualWidth/ActualHeight` 非零（宽度塌成 0 就是"有栏头但空白"）。
这个断言真的能给出文字宽高，比看图猜靠谱。

### 一处必须说明的编辑事故

这一轮我有三次用 Edit 工具时把 `old_string` 写成"注释行 + 换行"，`new_string` 写成
"注释行"（少了换行），结果是**把下一行代码拼到了注释后面**，比如
`/// <summary>…</summary>public sealed class MissingToBrushConverter`。
编译报错才发现。教训：**Edit 里 old/new 只在"确实要改内容"时用，不要用它当"看文件"的手段**；
要查看内容用 Read/Grep。改完结构性位置（using 段、类声明、文件尾）后立刻编译一次。

## 修复：悬浮窗「大小 / 透明」调不动 + 最小时裁切

用户报障（两个现象，一个根因）。

**根因：窗口尺寸在变，内容尺寸是写死的。** `FloatingWindow` 里 `SetExpandedSize()` 只算
`Width/Height = 236*scale`，但内容全是固定值（`WhaleImage Height="168"`、状态条、字号、外边距）。
于是放大时窗口大了鲸鱼不变（一片空），缩小时内容撑不下就越界。用探针量出来的实据：

```
改前  缩放 0.7：内容底边 219.8 / 窗口高 207.3   → 超出 12.5px（就是用户看到的裁切）
改前  缩放 1.6：鲸鱼渲染高 168，期望 268.8      → 内容根本不跟着放大
改后  缩放 0.7：内容底边 203.1 / 窗口高 207.3   ✓
改后  缩放 1.6：鲸鱼渲染高 269，期望 268.8      ✓
```

修法：`RootGrid.LayoutTransform = ScaleTransform`，让鲸鱼/文字/间距整体等比缩放；
尺寸和缩放系数收敛到唯一入口 `SizeFor(collapsed)`，用取整后的实际尺寸反算系数，
别处直接改 `Width/Height` 就会退回"窗口变了内容没变"。`RestorePosition()` 原来也漏了缩放，
所以启动时（保存的 scale=0.7）一开机就是裁切状态 —— 这条尤其重要。

**"调不动"的观感**来自两点，都修了：
1. 拖动时鲸鱼毫无反应（内容不缩放，只窗口动），放大缩小看不出区别；
2. 改动要等 700ms 的落盘节流结束才传给悬浮窗，拖动全程没反馈。
   现在新增 `FloatingWindow.PreviewScaleAndOpacity()`，拖动时实时套用，
   节流只负责最后写文件。

顺带：滑杆加 `IsMoveToPointEnabled`（点轨道任意位置即可跳过去，15px 的小手柄太难点）；
滑杆范围和设置校验统一到 `AppSettings` 的常量（原来 Sanitize 允许 0.6–2.0、滑杆是 0.7–1.6，
手改配置就会两边不一致）。

### 验证方式：先量数字，再修

这轮的顺序是「写探针 → 量出失败数字 → 修 → 复量」。探针 `ProbeSliders` /
`ProbeFloatingScale` 覆盖：Thumb 中心命中测试、`PART_Track` 宽度、真抛
`Thumb.DragDelta` 看值/读数/`_syncing` 守卫、逐档量内容底边与窗口底边的差值、

所以不能只看"滑杆能不能拖"就下结论，要一路量到"它要调的东西有没有变"。

## 修复：拖拽悬浮窗永远被当成点击

用户报："不管拖拽时间多久都会识别成点击进入主界面"。

**两层原因，都不是时长问题**：

1. 判定用的是"鼠标相对窗口的位置"：`PointToScreen(e.GetPosition(this))`。
   拖动时窗口跟着鼠标一起走，鼠标相对窗口的坐标几乎不变，算出来位移永远是 0。
2. 更隐蔽的一层：**`MouseLeftButtonUp` 是在 `DragMove()` 的模态移动循环内部派发的**，
   比 `DragMove()` 返回还早 —— 所以 `OnLeftButtonDown` 里那句
   `_movedWhilePressed = ...`（在 DragMove 之后）根本还没执行，Up 读到的是初始的 false。
   就算第 1 点修好了，时序不对照样是点击。

修法：记按下时的**屏幕坐标**（`System.Windows.Forms.Cursor.Position`）和窗口 `Left/Top`，
`HasMovedSincePress()` 在 Up 处理器里**独立算**；两个判据取或（光标位移 / 窗口被挪动），
后者兜住"拖出去又拖回来"。阈值 5 DIP 并按 DPI 换算成物理像素。
顺手删掉从未被启动过的 `_clickTimer`（死代码）。

**症状里有一个耐人寻味的细节**：修复前窗口拖完停在 (727,330)，不是按拖拽量算出来的
(600,420) —— 因为中途 `ShowMainWindow()`/`Activate()` 把焦点抢走了，打断了移动循环。
修好后位置精确停在 (600,420)，这本身就佐证了"拖拽中途被误触发点击"这个判断。

### 新增 `tools/drag_probe.py`（交互行为的实测探针）

这类行为没法靠断言测：`DragMove()` 是阻塞的、要走系统模态循环，只有真实输入能覆盖。
用 `SetCursorPos` + `mouse_event` 合成真实按下-移动-松开，判据是"松手后主面板有没有出现"。
三个场景：拖拽（不该打开）、原地单击（该打开）、从状态条拖拽（不该打开、也不该被误收起）。

**第一次的复现实验是无效的**：测试实例被单实例互斥挡掉了（弹了"已经在运行"），
合成点击打到了别的窗口，而检测到的"主面板"其实是本来就存在的屏外窗口。
教训：**测之前必须确认基线干净**（断言"窗口列表里没有主面板"），否则会把残留当成结果。
这个断言现在写进探针里了。

### 三个技术点

**加载外部图必须 `CacheOption=OnLoad` + `IgnoreImageCache`。** 前者不留文件句柄
（否则用户替换素材时被"文件正在使用中"卡住），后者避开 WPF 按 URI 的图片缓存
（否则改了文件内容界面上还是旧图）。

**只有明显大于显示尺寸的图才设 `DecodePixelHeight`**（阈值 2×540）。一张 4000×4000
不限制解码会白占几十 MB 内存；但小图设了会被插值放大再缩回去，白白变模糊。

**`GetResourceStream` 取不到时返回 null 是合法的** —— `Image.Source = null` 界面上只是
一片空白、不会有任何报错。所以"能不能加载出来"必须单独断言，否则图丢了没人知道。

## 发 1.1，顺带修掉参数解析的真 bug

版本改成 1.1.0（`WhaleLog.csproj` 的 `<Version>`）。关于页那行本来就是
`Assembly.GetName().Version` 读程序集，所以一处改完界面自动跟着变。
打包输出 `桌面\鲸记 WhaleLog 1.1.zip`（57.3 MB），删掉了旧的同名无版本号包。

准备生成出厂素材时撞见**一个真 bug**：

```
WhaleLog.exe --export-assets --quiet
```

`ArgValue("--export-assets")` 返回了 `"--quiet"` —— 取值逻辑只判断"下一个参数存在"，
不管它是不是另一个开关。于是素材被导出到工作目录下一个名叫 `--quiet` 的目录里。
`--shot --quiet`、`--shot-notes --quiet` 这类"开关后面不带值"的组合都会中招；
之前一直用 `--shot=<路径>` 的等号写法，所以一直没暴露。

修法：把参数解析从 `App.xaml.cs` 的局部函数提成 `Services/CommandLine.cs`，
下一个参数以 `-` 开头就视为没有值。提出来还有个好处 —— 能被自测直接编译验证，
这类边界在界面上完全看不出来，只有断言抓得住。自测加 12 项（151 → 163）。

误建的 `--quiet` 目录已清理。
