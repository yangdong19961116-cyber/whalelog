## 做了什么

### 1. 容器选型：实测 WPF 到底能播什么

新增 `tools/animprobe/`（独立 WPF 探针程序），把同一组带**羽化软边**的帧分别装进
GIF / APNG / 动画 WebP / PNG 序列 / 精灵图 PNG，看 WPF 各自解成什么样。
结论写死在 `Program.cs` 末尾，也输出到 `%TEMP%\whalelog-anim-probe\wpf-probe.txt`。

| 容器 | 能播 | 透明 | 便携性 |
|---|---|---|---|
| GIF | ✓ 帧数/时长准 | ✗ **仅 1 位**（解出 0/255 两级 alpha），边缘只能是硬的 | 全球通用 |
| APNG | ✗ WPF 只解第 1 帧 | — | — |
| 动画 WebP | ✓ | ✓ 8 位（解出 122 级） | ✗ 需 Store 包 `Microsoft.WebpImageExtension`，**非 Windows 默认组件** |
| PNG 序列 | ✓ 自己排帧 | ✓ 8 位 | 全球通用 |
| **精灵图 PNG** | ✓ 自己切帧 | ✓ 8 位 | 全球通用 ← **选定** |

→ **动态素材一律用「精灵图 PNG + 帧表 JSON」。**

顺带测到：**渲染时钟约 64Hz**，所以 24fps 能打满，帧率上限定 30 就够。

> 探针踩的坑：采样渲染时钟**必须跑真的消息循环**。用 `Thread.Sleep` 堵住 UI 线程
> 再去数 `CompositionTarget.Rendering` 的回调次数，会得出"渲染时钟不可用"的错误结论。

### 2. 规范画布：610 → 720

原本体 `DSniang1.png` 是 610×610，角色 bbox 是 (45,10)-(609,609) ——
**贴着画布的右边和下边**（左留 45 / 上留 10 / 右 0 / 下 0）。
任何向右的位移、横向拉伸、向下压扁立刻被裁：实测第一版 8 帧弹跳里 **6 帧被裁**
（2 帧裁右侧、4 帧裁顶部）。

于是定了一块有余量的规范画布（`tools/make_anim_sample.py` 文件头是规格的唯一来源）：

```
画布 720×720   角色高 600（占 83%）   横向居中 x=360   脚底基线 y=660
→ 上留 61 / 下留 59 / 左右各留 78（角色大小一点没变，只是四周有了余量）
```

唯一硬规则：**每帧角色的「横向中心」和「脚底」必须落在同一点**（x=360，脚底=660）。
帧间只允许整体垂直位移和绕该基准点缩放，横向中心绝不漂 ——
判据是每帧 alpha 边界框的横向中心一致（允差 2px，来自缩放取整）。

### 3. 产出三件套

| 产出 | 说明 |
|---|---|
| `tools/make_anim_sample.py` | 生成样例精灵图 + 帧表 + 预览图；**规格常量的唯一来源**，同时是参考实现 |
| `tools/check_anim_assets.py` | **交付前自检**，给画师跑。查三类返工原因：横向漂移（>2px 报错）、贴边裁切（余量 <2px 报错）、帧表与实际尺寸矛盾。退出码 0/1/2 |
| `outputs/样例-点击弹跳/` | 8 帧弹跳（4×2 网格）+ `whale.png` 静态本体 |
| `outputs/样例-眨眼示意/` | 4 帧眨眼（轮廓不变、零位移，这类动作不需要余量） |
| `outputs/动画素材规格/*.png` | 4 张规格说明图（含「对齐校验-本体与最高帧叠加」） |

帧表格式（`sheet.json`）定成：

```json
{
  "name": "clickBounce", "version": 1, "type": "sheet", "sheet": "sheet.png",
  "frameWidth": 720, "frameHeight": 720,
  "cols": 4, "rows": 2, "count": 8,
  "fps": 24, "loop": false,
  "anchor": { "x": 360, "y": 660 },
  "characterHeight": 600, "returnTo": "base", "sound": ""
}
```
