# 集成调研 · 把 dsh-pet 的动画素材与桌宠交互接进鲸记

> 调研时间：2026-09-20 · 结论：**技术上完全可行，但有一个硬约束（素材许可）和一个硬取舍（体积）需要先定**
> 本文是给下一轮对话的交接材料：读完这一份就能直接开工，不必重新调研。

---

## 0. 一句话结论

dsh-pet 的素材是 **640×360 / 24fps / VP9-alpha 透明 WebM**（106 个动作）；
鲸记能吃的只有 **720×720 精灵图 PNG**。两头对不上，中间必须做一次**离线转码**——
而这条转码链**本机已经实测跑通**（见第 4 节），不需要联网、不需要装系统级 ffmpeg。

真正的问题不是"能不能转"，而是三件事：

1. **许可**：素材是 CC BY-NC-SA 类同人素材，**只能个人非商业用**，必须署名（第 2 节）。
2. **体积**：106 个动作全转 ≈ **1.4 GB**，会把这个 58 MB 的便携包撑爆（第 6 节）。
3. **范围**：交互逻辑是 Python/Qt 的，**不能照搬**，只能把行为参数用 C# 重写（第 7 节）。

## 3. 素材实测规格（不是推测，是解出来的）

用 PyAV 与 ffmpeg 实际打开 `videos/idle/待机呼吸休闲.webm` 测到的：

| 项 | 值 |
|---|---|
| 容器 / 编码 | WebM / **VP9** |
| 尺寸 | **640 × 360** |
| 帧率 | **24 fps** |
| 时长 / 帧数 | 10.04 s / **241 帧**（实测解出 241 帧） |
| 透明 | ✅ 真 alpha。文件 stream metadata 带 `ALPHA_MODE=1`，解出来 **256 级 alpha** |
| 角色包围盒 | x[213,425] y[63,329] → **213 × 267**（与 manifest 的 `body_box` 一致） |
| 画布余量 | 角色只占 640×360 里的中间一小块，四周全是透明 |
| 单文件大小 | 311 ~ 608 KB（平均约 490 KB） |

**要点**：角色在源素材里只有 267 px 高，而鲸记的规范画布要求角色高 **600 px** →
转码时要放大 **2.25 倍**。放大后必须用 LANCZOS 重采样，否则边缘会糊。

## 4. 技术验证：转码链已经跑通（含一个坑）

### ✅ 可行路径

```bash
ffmpeg -c:v libvpx-vp9 -i <输入>.webm -pix_fmt rgba <输出>_%04d.png
```

实测结果（本机，2026-09-20）：

```
ffmpeg 7.1（含 --enable-libvpx）
frame_01.png: RGBA (640, 360)  alpha min 0 max 255
  → 透明 82.9% / 半透明像素 191513 / alpha 层级 255
```

**alpha 完整保留，羽化边缘 19 万个半透明像素都在。**

### ❌ 踩到的坑：PyAV 会静默丢 alpha

先装的 `av`（PyAV 18.1.0）解出来是 **`yuv420p`，alpha 全是 255**——
文件里明明有 `ALPHA_MODE=1`。`to_ndarray('rgba')` / `'bgra'` 都一样，
`'yuva420p'` 直接报 `Conversion to numpy array with format yuva420p is not yet supported`。

**结论：别用 PyAV 干这件事，它内置的 ffmpeg 构建不走 VP9 的 alpha 辅助流。**
用 imageio-ffmpeg 提供的**真 ffmpeg 二进制**（`imageio_ffmpeg.get_ffmpeg_exe()`）。

### 本机环境（已就绪，无需再配）

| 组件 | 状态 |
|---|---|
| `ffmpeg.exe` | 无系统级安装，但 **`imageio-ffmpeg` 自带 7.1**（venv 内），已验证可用 |
| `PyAV` | 已装但**不要用于取 alpha**（见上） |
| `Pillow` / `numpy` | venv `default` 里已有（12.3.0 / 2.5.3） |
| Python | 用 `C:\Users\Administrator\.workbuddy\binaries\python\envs\default\Scripts\python.exe` |

## 5. 目标格式：鲸记的精灵图规格

全在 `docs/动态素材规格.md`，这里只摘要点（**别重复造轮子，转码脚本要遵守它**）：

| 项 | 值 |
|---|---|
| 每格画布 | **720 × 720** |
| 角色高度 | **600 px**（与现有本体一致，屏幕上大小不变） |
| 横向中心 | **x = 360** |
| 脚底基线 | **y = 660** |
| 硬规则 | 每帧的横向中心与脚底必须落在同一点；横向**绝不能左右漂**（允差 2px） |
| 容器 | **精灵图 PNG + sheet.json**（GIF/APNG/WebP 都实测被否，见规格第 6 节） |
| 存放 | `Assets\anim\<动作名>\sheet.png` + `sheet.json` |

**这意味着转码要把 640×360 的源帧做三步几何变换**：

1. 按 alpha 包围盒裁出角色（源里角色只有 213×267）
2. 等比放大 2.247 倍 → 宽 479 × 高 600
3. 贴到 720×720 画布：横向居中（x 中心 360）、脚底对齐 y=660

> ⚠️ 第 3 步的"脚底"用固定值 **660**，但源素材里角色脚底会随动作上下移动
> （跳跃、伸展）。**必须让"静止态脚底"对齐 660**，而不是逐帧对齐——
> 逐帧对齐会把跳跃整个压平，动感全失。建议用 `body_box`（y=330）
> 对应的源坐标做锚点，按同一变换矩阵套用到每一帧。

## 6. 体积测算与取舍（必须用户定）

实测（同一帧内容，8 帧横向拼图后均摊）：

| 量 | 值 |
|---|---|
| 源帧 640×360 PNG | 115 KB |
| 放大贴到 720×720 后的**单张** PNG | 361 KB |
| 拼成精灵图后**每帧均摊** | **58 KB**（PNG 对相似帧压缩率极高） |
| 单动作（241 帧） | **≈ 13.7 MB** |
| 全部 106 个动作 | **≈ 1.42 GB** ❌ |

对比现状：鲸记整个便携包才 **58 MB**。全量集成会让它涨到 1.4 GB+，不现实。

### 三个可选档位

| 档位 | 动作数 | 预估体积 | 便携包总计 | 说明 |
|---|---|---|---|---|
| **精简（推荐先做）** | 8 个 | ≈ 110 MB | ≈ 165 MB | idle + turn + click×5 + drag |
| 标准 | 11 个 | ≈ 150 MB | ≈ 205 MB | 再加 move×3（会走动的桌宠） |
| 精选合集 | 20~25 个 | ≈ 280~340 MB | ≈ 340~400 MB | 再从 random 里挑最出彩的 |

进一步省体积的两条路（可叠加）：

- **降帧率到 12fps**（抽帧）→ 体积**减半**，桌宠动画基本看不出差别。
- **只对"每帧都在动"的动作保留全帧**，静态待机类抽帧更狠。

## 7. 交互模块：能移植什么、不能移植什么

源项目是 **PySide6/Python**，鲸记是 **WPF/C#**——**代码一行都不能直接搬**，
能搬的是**行为设计与参数**。`pet/catalog.py` 里这些常量可直接对应成 C# 常量：

| 源常量 | 值 | 含义 |
|---|---|---|
| `P_IDLE / P_TURN / P_ACTS` | 0.30 / 0.40 / 0.80 | 动画链概率：30% 待机、10% 转向、40% 动作、20% 移动 |
| `MOVE_MIN_PX / MOVE_MAX_PX` | 60 / 240 | 一次移动的距离区间 |
| `MOVE_MARGIN` | 20 | 屏幕边缘安全边距 |
| `MOVE_LEAD_SEC / TAIL_SEC` | 2 / 2 | 移动动画头尾各 2s 是准备/收尾，位置不动 |
| `DRAG_THRESHOLD` | 5 | 拖拽判定阈值（px） |
| `DEFAULT_SCALE / SCALE_STEPS` | 0.72 / (0.5, 0.72, 0.85, 1.0) | 显示缩放档位 |
| `CORNER_MARGIN` | 24 | 距屏幕右缘的默认间距 |

### 交互能力对照表

| dsh-pet 的能力 | 鲸记现状 | 移植难度 | 建议 |
|---|---|---|---|
| 待机呼吸 / 随机小动作 | 有（眨眼 + 4~9s 随机） | 低 | ✅ 换成 dsh 素材即可 |
| 点击回应（5 种随机） | 有（点击弹一下） | 低 | ✅ 直接升级 |
| 拖拽时播"悬空反馈" | 有拖拽 | 低 | ✅ 加上拖拽态动画 |
| **自主走动**（左右移动 ±60~240px） | ❌ 无 | **中** | ⭐ 最有价值的新能力 |
| **贴边吸附 / 屏幕边缘约束** | ❌ 无 | 中 | ⭐ 随走动一起做 |
| 气泡说话 / 情绪文案 | 有气泡 | 低 | 可接 |
| 多实例碰撞 IPC（两个桌宠相遇） | ❌ 无 | **高** | ❌ 不建议做，收益低 |
| 余额事件（events/balance 6 个） | — | — | ❌ 鲸记没有"余额"概念，无意义 |
| 上下文菜单 / 设置系统 | 鲸记已有自己的 | — | ❌ 不移植 |

> **一句话：值得移植的是"形象 + 点击/拖拽/待机 + 自主走动"这一层；
> dsh-pet 的菜单、设置、IPC、余额事件都不属于本次范围。**

## 8. 建议的实施顺序（下一轮可直接照做）

**第 1 步 · 转码工具（不碰主程序，风险最低）**

写 `tools/convert_dsh_webm.py`：

- 输入：`assets/characters/shenshen/videos/<类别>/<名字>.webm`
- 调 `imageio_ffmpeg.get_ffmpeg_exe()` 解帧 → RGBA PNG（**不要用 PyAV**）
- 按 `body_box` 定锚点，等比放大到角色高 600，贴进 720×720（中心 360 / 脚底 660）
- 拼精灵图 + 生成 `sheet.json`（格式照抄 `tools/make_anim_sample.py`，它是规格的唯一来源）
- 输出到 `Assets/anim/<动作名>/`
- **顺手把许可署名写进产物目录**

**第 2 步 · 先只转 2 个动作验证**（`待机呼吸休闲` + `点击回应-开心跃动`），
丢进 `Assets\anim\`，用鲸记现有的「重新加载素材」+ `--selfcheck` 验证能播、不跳、不裁边。

**第 3 步 · 跑通后再批量**（按用户选的档位），并处理体积（必要时抽帧到 12fps）。

**第 4 步 · 交互移植**：先是"点击回应随机挑一个动作"，再是"自主走动 + 贴边"。

**第 5 步 · 署名与文档**：`Assets\素材说明.txt` + 便携包《使用说明》+ HANDOFF 都要写清来源与许可。
