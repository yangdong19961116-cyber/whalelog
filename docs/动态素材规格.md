# 鲸记 WhaleLog · 动态素材规格

> 这份文档是给**做素材的人**看的：照着做一版动起来的小鲸鱼，放进素材目录就能用。
> 不需要看程序代码，也不需要会编程。
>
> 除了「动作」，还有**一张静态差分**（鼠标悬浮时换上的闭眼形象）也归这份管，
> 见第 2 节末尾「悬浮态形象」。
>
> 一句话版本：**按 720×720 的规范画布画一套帧，横向中心永远钉在 x=360、脚底钉在 y=660，
> 排成 4 列 2 行的精灵图，配一份 sheet.json，交付前跑一次校验脚本。**
>
> 配套的参考实现是 `tools/make_anim_sample.py`（跑一遍会生成样例和预览图），
> 交付前校验是 `tools/check_anim_assets.py`。

---

## 0. 为什么要有"规范画布"

原来的本体素材 `DSniang1.png` 是 610×610，角色**贴着画布的右边和下边**
（左留 45 / 上留 10 / 右 0 / 下 0）。

静止时这没问题，但一动就出事：任何向右的位移、横向拉伸、向下压扁都会立刻被裁掉。
实测第一版 8 帧弹跳里 **有 6 帧被裁**（2 帧裁右侧、4 帧裁顶部）。

所以规定一块四周有余量的画布：角色大小一点不变，只是搬家到画布中间。

## 1. 规范画布

| 项 | 值 | 说明 |
|---|---|---|
| 画布 | **720 × 720** | 每帧一格，正方形 |
| 角色高度 | **600 px** | 和现有本体一致，屏幕上大小不会变 |
| 横向中心 | **x = 360** | 画布正中 |
| 脚底基线 | **y = 660** | 角色的脚（最低的那行像素）落在这 |
| 四周余量 | 上 61 / 下 59 / 左右各 78 | 角色占画布高度 83% |

```
       y=0   ┌──────────────────────────────┐
             │                              │
             │         ↑ 上留 61            │
       y=60  │      ╭──────────╮            │
             │      │          │            │
             │      │   角色   │            │
             │  ←78 │  565×600 │ 78→        │
             │      │          │            │
             │      ╰──────────╯            │
      y=660  │ ─ ─ ─ ─ ─ 脚底基线 ─ ─ ─ ─ ─ │
             │         ↓ 下留 59            │
      y=719  └──────────────────────────────┘
                    x=360 ↑ 横向中心
```

### 唯一一条硬规则

**每一帧都必须让角色的「横向中心」和「脚底」落在同一个点上。**

帧与帧之间**只允许**：

- 整体垂直位移（跳起来 = 脚底 < 660）
- 绕该基准点的缩放（squash & stretch）

**横向中心绝对不能左右漂。** 判据是每帧角色 alpha 边界框的横向中心必须一致
（允差 2px，来自缩放取整）。漂了会怎样：播放时角色像被风吹一样左右扭。

### 垂直方向能走多远 —— 别按"上边留了 60px"算

脚底在 660、角色高 600，静止时头顶在 y=60，上边只剩 60px。
**但这 60px 还要装下纵向拉伸**：拉伸到 1.07 时角色高 642，光拉伸就把头顶顶到 y≈19，
留给"整体上移"的空间只剩十几像素。

第一版样例就是按"能上移 34px"写的，结果最高帧头顶落到 y = −15，被画布裁掉了
（校验脚本报「帧3（上）」）。

准确的算法：

```
头顶 y = 661 − round(角色高 × 纵向缩放) + 垂直位移     必须 ≥ 2
脚底 y = 头顶 y + round(角色高 × 纵向缩放) − 1         必须 ≤ 717
```

**拉伸越猛，能整体上移的额度越小。** 样例里最高帧是「纵向拉伸 1.07 + 上移 15px」，
头顶落在 y=4，离上边缘 4px —— 基本把可用空间用满了。

> 生成脚本 `tools/make_anim_sample.py` 会在写出文件**之前**逐帧打印余量，
> 不够就直接报错退出。改动画参数之后跑一遍它，不用等程序里播起来才发现。

## 2. 放在哪里

素材目录就是程序旁边的 `Assets\`（托盘菜单「打开素材目录」能直接打开）。
动态素材放在它的 `anim\` 子目录下，**一个动作 = 一个子目录**：

```
Assets\
  whale.png                 ← 静态本体（可选，见下）
  anim\
    base.png                ← 和精灵图同一套画布的静态本体（可选，但强烈建议给）
    clickBounce\            ← 一个动作一个目录，目录名就是动作名
      sheet.png
      sheet.json
    blink\
      sheet.png
      sheet.json
    alert\                  ← 可选
      sheet.png
      sheet.json
```

### 形象包（两套形象并存）

2026-09-20 起支持**多套形象**，每套有自己的素材根目录：

```
Assets\
  whale.png                     ← 「原版鲸鱼娘」的静态本体（沿用老布局，没动过）
  whale-hover.png               ← 原版的悬浮差分
  anim\                         ← 原版的动作
  characters\
    dsh\                        ← 「溟月 · 蓝鲸（新版）」← 出厂自带、默认形象
      whale.png                 ← 静态本体（384×384 格子）
      anim\idle-待机呼吸休闲\
        video.webm
        anim.json
      anim\clickBounce-开心跃动\
      ...（共 106 个动作）
      来源与许可.txt             ← 许可要求署名，**别删**
```

- 在 主面板 →「设置」→「桌面小鲸鱼」→「形象」里一键切换，**立刻生效、不用重启**
- 往 `characters\` 里再丢一个目录，程序会自动发现它（可以做自己的形象包）
- 设置里的值一旦给不出一个能用的形象，按 **设置里那个 → 默认形象 `dsh` → 原版** 逐级退，
  界面永远不会空着。分两种情况：
  - **值是个不存在的 ID**（手改过 `settings.json`、或自建的形象包被删了）→ 退到默认形象 `dsh`
  - **该形象的素材不在**（没随包发、目录被删）→ 退到 `dsh`；`dsh` 也不在才落到原版 `classic`
  - `classic` 是最后兜底：它的图是编译进程序集的嵌入资源，`Assets\` 整个不存在也在
- **原版形象没有搬家**：它的图仍然在 `Assets\` 根下，你以前放的东西一样有效

> 目录名（形象 ID）就是设置里存的值：`dsh` / `classic` / 你自建的名字。
> `classic` 是保留名，指向 `Assets\` 根本身。

**关于 `base.png`**：静止状态显示的就是它。它和精灵图用同一套画布
（默认规格 720×720；`dsh` 那套视频素材是 384×384），所以「静止 → 播放第一帧」不会看到尺寸跳变。
不给也行（静止时就用原来的 `whale.png`），但两张画布不一样时切换动作会看到角色大小跳一下。

**动作名不区分大小写**，下划线和连字符会被忽略，另外认几个别名：

| 动作 | 别名 | 什么时候播 |
|---|---|---|
| `clickBounce` | `click`、`tap`、`poke` | 单击小鲸鱼（打开主面板时） |
| `blink` | `idle`、`blinkidle`、`idleblink` | 闲置时随机（4~9 秒一次） |
| `alert` | `remind`、`reminder`、`notify`、`warning` | 到点提醒（没这个动作就退回原来的"整体上下弹一下"） |

目录名起成 `Click_Bounce` 这样也能认。**认不出来的目录名不会被主动播放**，
但也不报错 —— 你可以放自定义动作，只是程序不知道什么时候该播它。

> 同一个动作放两份（比如 `clickBounce\` 和 `Click-Bounce\`）只会生效一个：
> 目录名和动作名完全一致的那份优先，另一份会在诊断报告里记一条"重复"。

### 一个动作能做多少事：目录名的**前缀**决定角色

新版形象有一百多个动作，程序得知道"点一下该播哪个""闲下来该冒什么"。
这件事用**目录名的第一段**表达（第一个 `-` / `_` / 空格之前）：

| 前缀 | 角色 | 界面什么时候播 |
|---|---|---|
| `idle-` | 待机 | 平时**一直循环**播（有几条就随机挑一条） |
| `clickBounce-` | 点击回应 | 戳一下小鲸鱼；**有多条时随机挑一条** |
| `ambient-` | 闲置小动作 | 闲置时随机冒一个（25~70 秒一次） |
| `drag-` | 拖拽 | 真的拖起来之后循环播 |
| `alert-` | 提醒 | 到点提醒 |
| `move-` | 滑动 | 已登记，**当前没有交互会播它**（没做自主走动） |
| `turn-` | 转向 | 同上 |

前缀认不出来 → 该动作仍会被扫描、登记、能手动播，但界面不会主动播它。
一条 `idle-` 都没有时，退回"静态形象 + 偶尔眨眼"，行为和以前完全一样。

> 老素材不用改：目录名直接叫 `blink` / `clickBounce` / `alert` 的本来就各自是一个角色。

### 悬浮态形象（一张静态差分，不是动作）

鼠标移到小鲸鱼身上时，整张形象会换掉（比如换成闭眼版）。它**不是动作目录**，
就是一个文件，直接放在 `Assets\` 下：

```
Assets\
  whale.png          ← 平时显示的本体
  whale-hover.png    ← 鼠标悬浮时替换成这张（可选）
```

| 项目 | 说明 |
|---|---|
| 素材位名 | `whale-hover` |
| 认哪些文件名 | `whale-hover.png`、`closeeye.png`、`anim/closeeye.png` |
| 什么时候换 | 鼠标移入悬浮窗 → 换；移出 → 换回 |

**唯一的硬要求：和 `whale.png` 同画布、角色位置逐像素对齐。**
这两张是「同一时刻互相替换」的，对不齐就会看到角色在鼠标进出时**跳一下**。
（这和 `base.png` 不一样，那里画布不同只是切换动作时大小跳；这里是每一次进出都跳，最显眼。）

对齐有现成工具，别手工对：

```bash
python tools\prepare_expression.py 新图.png "Assets\whale-hover.png"
```

它会：抠掉纯色背景（白底 / 单色底都能处理）→ 缩放到基准画布 → 搜索最佳平移 →
打印 **IoU**。**IoU ≥ 0.98 才算合格**，低于这个值说明新图取景和 `whale.png` 差太多，
该让画师重出，而不是硬对。

输入图带透明通道时加 `--no-bg` 跳过抠背景；想顺手出张对齐差异图（红=本体多出、
青=新图多出、白=重合）加 `--diff`。

> 没配这个文件时**悬浮毫无变化**，不报错、不提示，安静回落 —— 所以它是纯可选的。

## 3. 精灵图怎么排

帧按**行优先**排进格子：先从左到右填满一行，再换下一行。

4 列 2 行 = 8 帧的排法：

```
  ┌────┬────┬────┬────┐
  │ 0  │ 1  │ 2  │ 3  │
  ├────┼────┼────┼────┤
  │ 4  │ 5  │ 6  │ 7  │
  └────┴────┴────┴────┘
```

所以精灵图的像素尺寸 = **帧宽 × 列数** × **帧高 × 行数** = 720×4 × 720×2 = **2880 × 1440**。

- 必须是 **PNG 且带透明通道**（其他格式没有可用的 alpha）
- 网格比帧数多出来的格子允许（比如 4×2 只放 6 帧），程序不会播多余的格子，
  但会在诊断日志里提一句

## 4. 帧表 `sheet.json`

```json
{
  "name": "clickBounce",
  "version": 1,
  "type": "sheet",
  "sheet": "sheet.png",
  "frameWidth": 720,
  "frameHeight": 720,
  "cols": 4,
  "rows": 2,
  "count": 8,
  "fps": 24,
  "loop": false,
  "anchor": { "x": 360, "y": 660 },
  "characterHeight": 600,
  "returnTo": "base",
  "sound": ""
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `sheet` | ✅ | 精灵图文件名。**只能是同目录下的文件名，不能带路径** |
| `frameWidth` / `frameHeight` | ✅ | 每格尺寸，规范画布就是 720 / 720 |
| `cols` / `rows` | ✅ | 网格列数 / 行数 |
| `count` | ✅ | 帧数。`cols × rows` 必须 ≥ 它 |
| `fps` | ⭕ | 帧率。**建议 ≤ 30**（悬浮窗很小，更高纯属浪费）。不写按 24 |
| `loop` | ⭕ | 是否循环。动作类一般 `false`（播一次就回静止） |
| `anchor` | ⭕ | 锚点，规范画布就是 `{"x": 360, "y": 660}`。不写按「横向居中、脚底贴下边」 |
| `characterHeight` | ⭕ | **角色在画布里的实际高度**，规范画布是 600 |
| `name` | ⭕ | 动画名，纯描述用 |
| `type` | ⭕ | 容器类型，认 `"sheet"`（精灵图）与 `"video"`（透明 webm）。写成 `"sequence"` 会被明确拒绝 |
| `version` / `returnTo` / `sound` | ⭕ | 预留字段，按样例填即可 |

### 另一种容器：透明视频（`type: "video"`）

不想画精灵图、或者手里已经有一段透明视频时，用这种写法。
**同一个 `anim\<动作名>\` 目录里改放 `video.webm` + `anim.json`** 即可，
目录名规则、角色前缀、切换逻辑全都一样。

```json
{
  "name": "idle-待机呼吸休闲",
  "type": "video",
  "video": "video.webm",
  "filter": "crop=384:360:128:0,pad=384:384:0:6:color=black@0,crop=384:384:0:0",
  "frameWidth": 384,
  "frameHeight": 384,
  "count": 241,
  "fps": 24.0,
  "loop": true,
  "characterHeight": 270,
  "anchor": { "x": 192.0, "y": 336.0 }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `video` | ✅ | 视频文件名，**只能是同目录下的文件名，不能带路径** |
| `filter` | ⭕ | ffmpeg 滤镜串，把源画面裁进格子。**只允许 `crop` / `scale` / `pad`** |
| `frameWidth` / `frameHeight` | ✅ | 解码后的**格子**尺寸，必须和滤镜的**输出**尺寸一致 |
| `count` | ⭕ | 视频可以不写：以实际解出多少帧为准 |
| `cols` / `rows` | ⭕ | 视频不需要排帧，自动给 `1×N` 占位 |
| 其余 | 同精灵图 | |

几条要紧的：

- **需要 `ffmpeg.exe`**。它在程序目录里（约 84 MB，GPL 许可，作为外部程序按需调用）。
  没有它程序照常跑，只是视频动作播不了，自检报告里会写明"没找到 ffmpeg"。
- **`filter` 会被原样拼进 ffmpeg 命令行**，所以程序把它当**不可信输入**校验：
  只放行 `crop` / `scale` / `pad`，参数只允许数字、`color=black@0`、`flags=lanczos`
  这类固定写法。写别的会被拒绝并说明原因（这是防命令注入，不是限制功能）。
- **编排交给工具**：帧表和滤镜都由 `tools/convert_dsh_webm.py` 生成，
  源画布 → 格子的换算只有那一处实现，离线校验和运行时用的是**同一个滤镜串**
  （两边各写一份的话会出现"校验通过、运行时错位"，非常难查）。
- **视频不需要预先转成 PNG**。实测：同样这批素材，PNG 精灵图要 1.82 GB，
  原样放 webm 只要 51.9 MB —— 差 35 倍，因为 VP9 有帧间预测，PNG 只能就帧论帧。
  程序运行时按 `filter` 逐帧解码，画质与源文件逐像素相同。


### `characterHeight` 为什么要写

程序要保证「换成精灵图之后，角色在屏幕上还是原来那么大」。
画布从 610 变成 720、角色还是 600 高，如果显示框还留原来的 168px，
角色就只剩 140px —— **凭空小 15%**，而且肉眼只会觉得"好像小了点"，很难定位。

所以显示框是按这个公式反算的：

```
显示框高度 = 角色的设计屏幕高度(165px) × 帧高 ÷ 角色像素高
           = 165 × 720 ÷ 600 = 198px
```

不写 `characterHeight` 就算不出来，程序会退回"保持原来的显示尺寸"——
画面不至于坏，但角色占比会和你画的不一致。

### 容错

- 帧表里可以带 `//` 注释和多余的逗号（手写时很容易带上，不该因此报废）
- `fps` 写超范围会被夹到 1~30 并提示
- 缺 `fps` / `anchor` / `characterHeight` 都能播，只是会在诊断日志里各提示一句
- **写错的帧表只影响它自己那一个动作**，不会让程序起不来

## 5. 交付前自检

```bash
python tools/check_anim_assets.py <素材目录或 sheet.json 路径>
```

例：

```bash
python tools/check_anim_assets.py outputs/样例-点击弹跳
python tools/check_anim_assets.py "C:/某处/Assets/anim/clickBounce"
```

退出码：`0` 全部通过 / `1` 有必须修的问题 / `2` 用法或文件错误。

它查三类最常见的返工原因：

| 检查 | 说明 |
|---|---|
| **横向漂移** | 每帧角色的水平中心是否一致（> 2px 报错） |
| **画布裁切** | 是否有帧的内容贴到画布边缘（余量 < 2px 报错） |
| **帧表对不上** | `frameWidth`/`cols`/`count` 和精灵图实际尺寸是否矛盾 |

判据全是「阈值 + 打印实测值」，不猜、不掩盖 —— 有偏差就把数字摆出来，
由你决定是改素材还是调容差。

样例素材的输出：

```
  ✓ 帧表字段完整（6 项必需字段都在）
  ✓ 网格容得下：4×2 = 8 ≥ 8 帧
  ✓ 精灵图带透明通道（模式 RGBA）
  ✓ 精灵图尺寸与帧表一致：2880×1440
  ✓ 网格可整除：4 列 × 2 行
  ✓ 8 帧都有内容
  ✓ 横向中心一致：359.0 ~ 360.0（漂移 1.0px ≤ 2px）
  ✓ 实测中心与帧表 anchor.x=360 吻合
  ✓ 没有帧贴到画布边缘（余量 ≥ 2px）
  ✓ 各帧角色高度在合理范围：558 ~ 642px（波动 13%）
  ✓ 帧率 24 fps
  ✓ 静态本体与帧表同画布：720×720
  ✓ 静态本体的横向中心 360.0 与帧表锚点一致
结论：全部通过（13 项）
```

## 6. 用哪种容器（实测结论，别重测）

容器选型是实测过的，结论写在 `tools/animprobe/`（一个独立的 WPF 探针程序，
结论也写死在该程序的 `Program.cs` 末尾）：

| 容器 | 能播 | 透明 | 便携性 |
|---|---|---|---|
| GIF | ✓ 帧数/时长准确 | ✗ **只有 1 位**，边缘只能是硬的 | 全球通用 |
| APNG | ✗ WPF 只解第 1 帧 | — | — |
| 动画 WebP | ✓ | ✓ 8 位可羽化 | ✗ 需要 Store 包 `Microsoft.WebpImageExtension`，**不是 Windows 默认组件** |
| PNG 序列 | ✓ 自己排帧 | ✓ 8 位 | 全球通用 |
| **精灵图 PNG** | ✓ 自己切帧 | ✓ 8 位 | **全球通用 ← 手画素材走这条** |
| **透明 webm（VP9-alpha）** | ✓ 用 ffmpeg 解码 | ✓ 8 位可羽化 | 需要一个 `ffmpeg.exe`，但**体积小 35 倍** ← 现成视频走这条 |

实测依据：同一组带羽化软边的帧，GIF 解出来只有 2 级 alpha（0/255），
WebP 和 PNG 都解出 122 级。**所以手画的素材一律用精灵图 PNG。**

**如果你手里已经是视频**（尤其是那种一百多个动作的成套素材），别转成 PNG：

| | PNG 精灵图 | 源素材 VP9-alpha |
|---|---|---|
| 压缩率 | 约 3 倍 | 约 100 倍 |
| 106 个动作 / 25423 帧 | 1.82 GB | **51.9 MB** |

差距不在帧数、也不在 alpha 通道（像素里 RGB 占 86%），而在 **VP9 的帧间预测** ——
这类连续画面逐帧存 PNG 是纯粹的浪费。所以程序支持 `type: "video"`：
**原样搬 webm，运行时逐帧解码**，画质与源文件逐像素相同。
怎么生成见 `tools/convert_dsh_webm.py`（它就是给自带的「溟月」形象用的）。

## 7. 做好之后怎么验

1. 把 `sheet.png` + `sheet.json` 放进 `Assets\anim\<动作名>\`
2. 把同画布的静态本体放成 `Assets\anim\base.png`
3. 托盘图标右键 → **「重新加载素材」**
4. 点一下小鲸鱼 → 应该弹一下；放着不动 → 4~9 秒眨一次眼

**看不到效果时按这个顺序查**：

| 现象 | 多半是 |
|---|---|
| 完全没反应 | 素材不在 `Assets\anim\<动作名>\` 下；或者目录名认不出来 |
| 鲸鱼变小了 | 帧表没写 `characterHeight` |
| 每次跳到最高点就少一截 | 角色顶到画布边缘了 —— 跑校验脚本，它会把离边最近的那帧指出来 |
| 播放时左右扭 | 横向中心漂了 —— 跑校验脚本 |
| 只播了一帧就不动了 | `count` 和实际帧数不符，或者 `cols`/`rows` 写反了 |

**最权威的排查入口**：托盘图标右键 → 退出鲸记，然后命令行跑

```bash
WhaleLog.exe --selfcheck
```

结果写在 `%AppData%\WhaleLog\logs\selfcheck.log`，里面「小鲸鱼动画」一节会写明：
程序看了哪个目录、认出了几个动作、哪一份没认出来、以及为什么。
